P24 Adapter 代码详解：逐行拆解手写 ViT 前向与并行 Adapter 分支

2026-11-28 #ViT#PyTorch#timm#Adapter#参数高效微调#代码详解

〇、先说清楚这一节难在哪

5.3 讲的是思想，5.4 是把它写成代码。这一节之所以听起来吃力，是因为它不是”照 timm 的接口调一下”这么简单，而是遇到了一个真实工程矛盾：

timm 提供的 vit_small_patch16_224，它的 blocks 是一个 nn.Sequential，每个 Block 的 forward 是写死的（x = x + attn(norm1(x))，x = x + mlp(norm2(x))）。
我们想在里面并联一条 adapter 分支，但没法只改一行就插进去。

于是课程选了最直接的办法：把 ViT 的整个前向过程手写一遍，在 12 个 block 的循环里，自己控制”原 MLP 输出”和”adapter 输出”怎么相加。这样做的好处是完全可控，坏处是你必须把 ViT 前向的每一步都亲手补回来——这也是这一节代码看起来长的原因。

整节代码只有三块，按顺序读就不会乱：

序号 代码块 作用 难度
1 AdaptMLP 定义 adapter 小模块本身（down→ReLU→up） 简单
2 Adapter.__init__ 冻结主干 + 给 12 个 block 各挂一个 AdaptMLP + 换分类头 中等
3 Adapter.forward 手写 ViT 前向，在 MLP 处并联 adapter 本节难点

下面每一段都是”先给代码，再给逐行注释表“，代码里不放注释，注释单独写，方便对照。

一、第 1 块：AdaptMLP —— Adapter 的瓶颈模块

这一块是 5.3 那个 Down → ReLU → Up 的代码化，全文只有 10 行，但它是整个方法的核心。

逐行注释

行 代码 注释
1 class AdaptMLP(nn.Module): 定义一个自定义模块。继承 nn.Module 后，PyTorch 才会自动登记它内部的 nn.Linear 参数，.parameters()、.to(device)、.train()/.eval() 才能作用到它们身上。名字叫 AdaptMLP 是因为课程把 adapter 实现成了”两层 MLP 组成的瓶颈”
2 def __init__(self, input_dim, hidden_dim): 构造参数只有两个。input_dim = 要接进哪个维度（ViT-Small 是 384，课程口头举例用的是 1024，只是举大模型的例子）；hidden_dim = 瓶颈维度（课程用 64）
3 super(AdaptMLP, self).__init__() 调用父类 nn.Module 的初始化。必须写，否则后面 self.down_proj = ... 赋值时会报 “cannot assign module before Module.init() call”
4 self.down_proj = nn.Linear(input_dim, hidden_dim) 下采样层（down projection）。把 [..., 384] 压到 [..., 64]。nn.Linear 会自动创建权重 W: [hidden_dim, input_dim] 和偏置 b: [hidden_dim]，并默认 requires_grad=True
5 self.relu = nn.ReLU(inplace=True) 中间的非线性激活。这一步不能省：如果只有两层线性，W_up(W_down·x) = (W_up·W_down)·x 仍然是一个线性变换，等于什么非线性都没加。inplace=True 表示原地修改，省一点显存
6 self.up_proj = nn.Linear(hidden_dim, input_dim) 上采样层（up projection）。把 [..., 64] 还原回 [..., 384]。注意方向和 ViT 原 MLP 相反：原 MLP 是先升维再降维，adapter 是先降维再升维
7 （空行） —
8 def forward(self, x): 定义前向计算。x 的形状是 [B, N, 384]（B=batch，N=token 数，ViT-Small 中 N=197）
9 x = self.down_proj(x) 下采样：[B, 197, 384] → [B, 197, 64]。nn.Linear 只作用在最后一维，前面维度原样广播，所以 batch 和 token 维度完全不受影响
10 x = self.relu(x) 非线性：形状不变 [B, 197, 64]，负数清零
11 x = self.up_proj(x) 上采样：[B, 197, 64] → [B, 197, 384]。输出维度必须回到 384，否则后面和原 MLP 输出相加时形状对不上
12 return x 返回这一支的输出，形状 [B, 197, 384]，与输入同形。正因为它同形，才能和原 MLP 的输出直接相加

参数量算一下

384×64 + 64（down）+ 64×384 + 384（up）= 24,576 + 64 + 24,576 + 384 = 49,600，约 5 万参数。

对比一个 ViT-Small block 里的原 MLP（384→1536→384）：384×1536 + 1536 + 1536×384 + 384 ≈ 1.18M。adapter 只有原 MLP 的 4%。12 个 block 全挂上也才 60 万参数左右，占 ViT-Small 22M 的 2.7%。

二、第 2 块：Adapter 类的 __init__ —— 冻结 + 挂模块 + 换头

这一段做三件事，顺序不能错：先冻结主干 → 再给每个 block 挂 adapter → 最后换分类头。

逐行注释

行 代码 注释
1 class Adapter(nn.Module): 整个”带 adapter 的 ViT”模型类。注意它是一个完整模型，不是一个小模块——里面既装了 backbone，又装了 12 个 adapter，还装了 head
2 def __init__(self, num_classes, hidden_dim): num_classes = 下游任务类别数（CIFAR-10 是 10）；hidden_dim = adapter 的瓶颈维度（课程用 64）
4 self.vit = timm.create_model('vit_small_patch16_224', pretrained=True) 建 ViT-Small：patch 尺寸 16×16，输入 224×224（所以 196 个 patch），embed_dim=384，12 层 block，12 个 attention head。pretrained=True 自动下载并载入 ImageNet 预训练权重——这是”迁移”的前提
6 for param in self.vit.parameters(): 遍历整个 backbone 的所有参数：patch_embed 的卷积核、12 个 block 里的 qkv/proj/MLP/LayerNorm、最后的 norm、以及原来的 1000 类分类头
7 param.requires_grad = False 把梯度开关全部关掉。之后 loss.backward() 不会为这些参数计算梯度，optimizer.step() 也就改不动它们。这就是”主干冻结”在代码层面的全部含义
9 self.adapter_mlps = nn.ModuleList() 准备一个容器，用来装 12 个 AdaptMLP。必须用 nn.ModuleList，不能用普通 []：普通 list 里的 nn.Module 不会被登记进 self._modules，后果是 self.parameters() 拿不到它们、optimizer 优化不到、.to(device) 也不会搬它们，而且保存 state_dict 时会整个丢失（见文末”可改进点 1”）
10 for i, block in enumerate(self.vit.blocks): 遍历 ViT 的 12 个 block。self.vit.blocks 是 nn.Sequential，enumerate 同时给出序号 i（0~11）和 block 对象。序号 i 不能丢，因为后面 forward 里要靠它取”这个 block 对应的 adapter”
11 for param in block.parameters(): 再对这个 block 单独遍历一次参数
12 param.requires_grad = False 又冻结一遍。这一步在上一行已经全覆盖过，这里是课程故意写出的”双保险”，口语里也强调了”方便遍历：把原有 ViT block 的参数冻结”。重复设置 False 不会有副作用，只是冗余
13-15 self.adapter_mlps.append(AdaptMLP(input_dim=self.vit.embed_dim, hidden_dim=hidden_dim)) 为这个 block 新建一个独立的 adapter，压进容器。三个要点：①input_dim 取 self.vit.embed_dim（=384，ViT-Small 的特征维度），也可以写死 384；②每个 block 一个 adapter，12 个 adapter 互不共享权重；③hidden_dim 由用户传进来（64），是整个方法唯一的”旋钮”——越小越省参数，越大越能适配
17 self.vit.head = nn.Linear(self.vit.head.in_features, num_classes) 把 1000 类分类头换成 10 类头。self.vit.head.in_features 是原头的输入维度 384。新建的 nn.Linear 默认 requires_grad=True，而且它是在冻结循环之后才创建的，所以不会被冻住——这个顺序很关键，和第 5.2 节 linear probing 的坑是同一个

这件事做完之后，模型里到底哪些参数可训练？

参数来源 状态 有没有被优化器更新
self.vit 全部（patch_embed / 12 个 block / norm） requires_grad=False 不更新
旧的 head（1000 类） 已被替换掉，不再存在于计算图 —
新的 self.vit.head（10 类） requires_grad=True 更新
self.adapter_mlps[0..11] 共 12 个 AdaptMLP requires_grad=True 更新

三、第 3 块：forward 手写 ViT 前向 —— 为什么这么长

先说清思路：原版 ViT 的 forward 是这么写的（伪代码）：

课程要在 x = x + mlp(norm2(x)) 这一步并联 adapter，所以把它展开成：

其余步骤一行不改地照抄。所以整段 forward 可以拆成 5 段来读：

段 行范围 干什么
① 切 patch patch_embed [B,3,224,224] → [B,196,384]
② 拼 cls token cls_token.expand + cat [B,196,384] → [B,197,384]
③ 加位置编码 pos_embed + pos_drop 形状不变 [B,197,384]
④ 12 个 block 循环 前半 attention 残差 / 后半 MLP+adapter 形状不变
⑤ 收尾 norm + 取第 0 个 token + head [B,197,384] → [B,10]

3.1 段①②③：切 patch、拼 cls token、加位置编码

行 代码 注释
1 def forward(self, x): 输入 x 是一个 batch 的图像张量，形状 [B, 3, 224, 224]（3=RGB 通道，224×224 是 Resize 后的尺寸）
2 x = self.vit.patch_embed(x) 切 patch + 线性映射，一步完成。内部是一个 kernel=16, stride=16 的卷积：把图像切成 14×14=196 个 16×16 的小块，每块映射成 384 维向量。输出 [B, 196, 384]。等价说法：196 = (224/16)²，384 = embed_dim
4 if self.vit.cls_token is not None: 判断这个 ViT 是否使用 cls token。timm 的 ViT 默认有（class_token=True），所以这个分支会进来。之所以要判断，是因为有些变体用 global average pooling 代替 cls token，那时就没有这一步
5 cls_tokens = self.vit.cls_token.expand(x.shape[0], -1, -1) cls_token 是一个可学习的向量，形状 [1, 1, 384]（只有一份，属于 backbone 参数，已冻结）。expand(B, -1, -1) 把它在 batch 维上”复制” B 份，得到 [B, 1, 384]。注意 expand 不真的复制内存，只改 stride，所以省显存
6 x = torch.cat((cls_tokens, x), dim=1) 在第 1 维（token 维）把 cls token 拼到最前面：[B,1,384] 与 [B,196,384] 拼接 → [B,197,384]。拼接后第 0 个 token 永远是 cls token，这个”位置约定”是后面 x[:, 0] 能取到分类特征的前提
8 if self.vit.pos_embed is not None: 判断是否有可学习位置编码。ViT 必须有（否则 Transformer 对 token 顺序完全无感，图像的空间结构就丢了）
9 x = x + self.vit.pos_embed.expand(x.shape[0], -1, -1) 加上位置编码。pos_embed 形状 [1, 197, 384]（第 0 个位置对应 cls token，后 196 个对应 196 个 patch），expand 成 [B, 197, 384] 后逐元素相加。为什么要 expand：pos_embed 只有一份，batch 内每张图共用同一套位置编码
11 x = self.vit.pos_drop(x) 对加完位置编码的 token 做 dropout（timm 里 pos_drop 是 nn.Dropout(p=pos_drop_rate)，默认 p=0）。只改数值、不改形状，形状仍 [B,197,384]

3.2 段④前半：12 个 block 里的 attention 路径（残差照抄原版）

行 代码 注释
1 for i, block in enumerate(self.vit.blocks): 依次流过 12 个 Transformer block。i 用来取对应的 adapter（self.adapter_mlps[i]），block 是本层冻结的注意力+MLP
2 block_input = x 把进入本层的 x 先存一份。这份”快照”就是残差连接要加回去的恒等项。之所以要专门存，是因为第 3 行会把 x 覆盖成 norm 之后的版本，原值就丢了
3 x = block.norm1(x) 第 1 个 LayerNorm（Pre-Norm 结构：先归一化再进子层）。形状不变 [B,197,384]，作用是稳定数值，让 attention 的输入分布可控
4 x = block.attn(x) Multi-Head Self-Attention：12 个头，每个头 32 维（384/12），输出拼回 384 维。这一步做全局 token 之间的信息交换——每个 patch 都能看到其他所有 patch。形状不变 [B,197,384]
5 x = block_input + x 残差相加：把快照 block_input 加上 attention 的输出。这一行等价于原版 ViT 的 x = x + attn(norm1(x))。残差的作用是让梯度有一条”高速公路”直通浅层，22M 参数的深网络才训得动
6 （空行） 下面进入本节真正改写的地方

3.3 段④后半：MLP 与 adapter 两路并行相加（本节核心）

行 代码 注释
1 original_mlp_output = block.norm2(x) 第 2 个 LayerNorm。注意变量名虽然叫 original_mlp_output，这一步其实只是归一化，还没过 MLP，名字是课程起的，读的时候别被带偏
2 original_mlp_output = block.mlp(original_mlp_output) 走原 MLP 这条路：384 → 1536 → GELU → 384（timm ViT 的 mlp_ratio=4）。这一层参数已冻结，只做前向、不产生梯度。输出 [B,197,384]
4 adapt_mlp_output = self.adapter_mlps[i](x) 走新加的 adapter 这条路：x → down(384→64) → ReLU → up(64→384)，输出 [B,197,384]。三条要点：①输入用的是 x，即 attention 残差相加之后、未经过 norm2 的 hidden state，所以原路和 adapter 路吃的是”同一份 x”的两个分支（并行而非串行）；②self.adapter_mlps[i] 里存的正是第 i 个 block 专属的 adapter；③这一路参数可训练，梯度会回传到它
6 x = original_mlp_output + adapt_mlp_output 两路输出逐元素相加，结果作为本层输出，形状 [B,197,384]。这就是 5.3 那张图的代码化：原 MLP 输出 + adapter 输出。这一步等价于在残差结构里”多绕了一个模块再汇入相加点”

一句话记住这段：x = MLP(norm2(x)) + Adapter(x)。原路不变，新路并联，两路同形相加。

3.4 段⑤：收尾 —— 归一化、取 cls token、过分类头

行 代码 注释
1 x = self.vit.norm(x) 12 层跑完后，对全部 token 再做一次 LayerNorm（timm 里叫 norm，也就是整个 ViT 的 final norm）。形状 [B,197,384]。这一步不能省：最后一层的输出没有归一化，数值范围不稳定，直接接分类头会掉点
3 if self.vit.cls_token is not None: 同样先判断有没有 cls token
4 x = x[:, 0] 只取第 0 个 token（cls token）：[B,197,384] → [B,384]。为什么只取它？因为 cls token 从第 0 层开始就和所有 patch 做 attention，是唯一一个”聚合了全图信息”的向量；而 196 个 patch token 各自只代表局部。ViT 的分类就是拿这个全局向量去做分类
6 x = self.vit.head(x) 过分类头：[B,384] → [B,10]，得到 CIFAR-10 的 10 类 logits（未经过 softmax）。这一层是新建且可训练的
7 return x 返回 logits，供外面用 nn.CrossEntropyLoss() 计算损失（该损失内部自带 softmax，所以这里不要手动加）

四、把所有形状串成一张表（背下来就不容易晕）

阶段 代码 形状 谁在变
输入 x [B, 3, 224, 224] —
切 patch patch_embed(x) [B, 196, 384] 196 = (224/16)²
拼 cls cat((cls_tokens, x), dim=1) [B, 197, 384] +1 个 token
加位置编码 x + pos_embed [B, 197, 384] 不变
dropout pos_drop(x) [B, 197, 384] 不变
attention 路 block_input + block.attn(norm1(x)) [B, 197, 384] 不变
原 MLP 路 block.mlp(norm2(x)) [B, 197, 384] 中间曾到 1536，出来回 384
adapter 路 adapter_mlps[i](x) [B, 197, 384] 中间到 64，出来回 384
两路相加 orig + adapt [B, 197, 384] 不变
final norm vit.norm(x) [B, 197, 384] 不变
取 cls x[:, 0] [B, 384] 去掉 196 个 patch token
分类头 vit.head(x) [B, 10] 10 类 logits

三个”魔法数字”的来源：196 来自 (224/16)²，197 = 196 + 1（cls token），384 来自 ViT-Small 的 embed_dim。换模型时这三个数字都会变（ViT-Base 是 768），代码里尽量用 self.vit.embed_dim 而不是写死 384。

五、和前两节放在一起看

线性探测 全微调 Adapter
主干参数 冻结 更新 冻结
新增模块 只有一个线性头 无 12 个瓶颈模块 + 头
可训练参数 ≈3.8K 22M ≈600K
是否要改前向 不用 不用 要，必须手写 forward
适配能力 弱 强（易过拟合） 中（性价比最高）

Adapter 唯一”麻烦”的地方就是第三节那段手写 forward。理解了”原路不变、新路并联、同形相加“这十二个字，那 20 行代码就只是把 ViT 原来藏在 timm 里的前向过程摊开摆给你看。

六、课程代码的四处可改进点（读懂后再看这段，能少踩坑）

课程代码是为了讲清原理，直接拿来跑会有几个小问题。这里逐条列出，都属于”知道就好”的工程细节。

1. self.adapter_mlps = [] 用普通 list 装模块（最严重）

普通 Python list 不会把里面的 nn.Module 登记为子模块，后果是：

  • model.parameters() 里看不到这 12 个 AdaptMLP 的参数；
  • 于是 optimizer = torch.optim.Adam(model.parameters(), ...) 根本不会更新 adapter —— 你以为在训 adapter，实际只有 head 在动；
  • model.to('cuda') 不会搬移它们；state_dict() 保存模型时它们整个丢失。

修正：用 nn.ModuleList()（本文第二节代码已按修正版写）。若坚持先建 list 再赋值，也必须在该模块 __init__ 里给 nn.ModuleList 赋值一次，不能是裸 list。

判断标准：写完打印一下

Adapter 版应该是 60 万量级；如果只有 3 千多，说明 adapter 没被登记进去。

课程写的是：

严格对应原版 ViT 的残差结构应该是：

也就是”进 MLP 之前的 x + 原 MLP 输出 + adapter 输出”三项相加。课程版本少了恒等项，等价于把残差连接去掉了，深层网络会难训、且和”在原残差上做加法”的原意有偏差。工程上建议补上（注意 block_input 在第 2 行已被覆盖，需要另存一个变量，如 mlp_input = x）。
