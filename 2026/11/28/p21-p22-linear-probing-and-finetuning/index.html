P21-P22 线性探测与微调：ViT 下游迁移代码笔记

2026-11-28 #ViT#迁移学习#Linear Probing#Fine-tuning#CIFAR-10#timm

一、视频信息与本节定位

项目 内容
稿件 BV1E9U8BBEvZ（B站强推！全网最全最详细的多模态大模型教程）
分P P21（5.1 线性探测与微调，05:22）、P22（5.2 线性探测与微调代码详解，05:40）
技术线 从零训练 → 自监督预训练（MAE/MoCo）→ 有监督对比（CLIP）→ 预训练模型的三种下游迁移方式（线性探测 / 微调 / Adapter）
本节定位 下游迁移的第一、二种方式。核心问题不是”怎么写模型”，而是**”预训练权重拿来之后，到底放开哪些参数去学”**

预训练模型（ViT-Small/16，在 ImageNet 上训过）已经学会通用视觉特征，现在要它输出 CIFAR-10 的 10 个类别。原分类头是 ImageNet 的 1000 类，必须换掉。换掉之后有两种选择：

  • Linear Probing（线性探测）：主干预训练权重全部冻结，只训新分类头。
  • Fine-tuning（微调）：主干和新分类头一起训。

这两种做法对应两个不同的科学问题：前者问”预训练特征本身够不够好”，后者问”让特征提取器再适应一下新任务能不能更好”。

二、先把两个概念分清楚

1. Linear Probing（线性探测）

一句话：把预训练 ViT 当作固定的特征提取器，不让它学习新东西，只训练最后新加的线性分类头。

模块 状态
ViT 主干（patch embed + 12 个 block + norm） 冻结，requires_grad = False
新分类头 nn.Linear 可训练

它的实验含义：如果只用一个线性分类器就能把 CIFAR-10 分开，说明预训练特征里已经含有足够好的判别信息。所以线性探测常被当作评价自监督预训练质量的标准探针（MAE、MoCo 论文里都用它做 main result 表格）。

2. Fine-tuning（微调）

一句话：不只训练新分类头，还允许预训练 ViT 主干继续调整参数，让它适应新任务。

模块 状态
ViT 主干 可训练
新分类头 nn.Linear 可训练

它的实验含义：给特征提取器一点自由度，让它把通用特征改造成 CIFAR-10 专用的特征。代价是容易过拟合小数据集，学习率要调小（课程里线性探测用 1e-3，全模型微调用 1e-4 这个量级）。

3. 最容易混淆的地方（这节最容易考的点）

Linear Probing 里的 “Linear” 指的是**”只训练一个线性读出头”这一实验策略**；代码里的 nn.Linear 是一个具体的线性层。

模型里出现 nn.Linear 完全不代表你在做 linear probing——FineTuning 类里也有 nn.Linear（新分类头）。

判断标准只有一条：看哪些参数的 requires_grad 是 True。

三、模型定义：逐行看懂代码

1. FineTuning 类

逐句说明：

  • nn.Module：PyTorch 自定义模型统一继承它，才能被 model.parameters()、.train()、.to(device) 正常管理。
  • timm.create_model("vit_small_patch16_224", pretrained=True)：一行搭出 ViT-Small，patch 16×16，输入 224×224，pretrained=True 表示顺带下载并加载 ImageNet 预训练权重。这一步就是”迁移”的来源。
  • self.vit.head.in_features：读原分类头接收的特征维度。ViT-Small 的 embed_dim = 384，所以这里是 384。
  • self.vit.head = nn.Linear(in_features, num_classes)：把 1000 类头换成 10 类头。新头是随机初始化的，所以它必须可训练，否则整个模型输出的永远是随机结果。
  • forward：不做任何额外处理，直接 self.vit(x)。因为 Fine-tuning 的差别不在前向计算，而在优化器会更新哪些参数。

关键点：这个类里没有写任何冻结代码，self.vit 的全部参数默认 requires_grad=True，所以梯度会一路回传到 patch embedding。

2. LinearProbing 类

和 FineTuning 只差三行，但语义完全不同：

  • for param in self.vit.parameters(): param.requires_grad = False：把 ViT 的所有参数（包括原分类头） 的梯度开关关掉。之后 loss.backward() 不会算、也不会存这些参数的梯度，optimizer.step() 自然改不动它们。
  • self.vit.head = nn.Linear(self.vit.head.in_features, num_classes)：在冻结之后再新建分类头。

顺序坑（很容易踩）：如果先建新头再执行冻结循环，新建的 head 也会被 requires_grad = False 冻住，整个网络就没有任何可训练参数，训练 loss 会一直不动。课程强调的”先冻结原 ViT，再创建新分类头”就是这个原因。

另一层保险：新建的 nn.Linear 默认 requires_grad=True，所以只要它是在冻结循环之后赋值进去的，就不会被冻。

3. 两种写法在参数层面差多少

项目 LinearProbing FineTuning
可训练参数 384×10 + 10 ≈ 3.8K ViT-Small 全部 ≈ 22M
显存（激活 + 梯度） 很小，主干不需要存梯度 大，主干要存激活与梯度
收敛速度 快，几个 epoch 就有结果 慢，需要更多 epoch 和调学习率
过拟合风险 低 高（尤其 CIFAR-10 只有 50K 张）

可以把 sum(p.numel() for p in model.parameters() if p.requires_grad) 打印出来验证：linear probe 时应该只有几千，fine-tune 时是两千万级。

四、数据：为什么必须 Resize 到 224

CIFAR-10 原图只有 32×32，而 vit_small_patch16_224 里的 224 指模型期望的输入分辨率 224×224（14×14 = 196 个 patch，每个 patch 16×16）。ViT 的 patch embedding 是固定尺寸的卷积核，位置编码长度也按 197 个 token 固定，所以分辨率不能随便改。

  • Resize((224, 224))：把 32×32 放大到 224×224。这是”小图放大”，会损失细节，但为了复用 224 预训练权重，这一步是必须的妥协。
  • ToTensor()：把 PIL 图像转成 torch.float32，形状 [3, 224, 224]，数值缩放到 [0,1]。
  • DataLoader(..., batch_size=4, shuffle=True)：batch_size=4 是为了显存友好（课程演示环境），真实实验可用 32/64/128；shuffle=True 打乱顺序，避免同类样本连续出现导致梯度抖动方向一致。

形状推理链（贯穿全节，务必记住）：

阶段 形状
一个 batch 输入 [4, 3, 224, 224]
patch_embed 之后 [4, 196, 384]
拼上 cls token [4, 197, 384]
分类头输出 logits [4, 10]
标签 [4]

196 = (224/16)²，197 = 196 + 1（cls token），384 是 ViT-Small 的 embed_dim。这三个数字在后一节 Adapter 里还会反复出现。

七、和 SAM2 / 变化检测的联系

把这两个策略映射回自己的研究方向（弱监督变化检测、SAR/光学联合变化检测）：

做法 对应哪一类
冻结整个图像编码器，只训变化检测头 接近 linear probing，但检测头通常是卷积/多层结构，不是单纯 nn.Linear，严格说不叫 strict linear probing
冻结大部分，只解冻最后 1-2 个 stage + 检测头 部分微调（partial fine-tuning）
全部解冻一起训 full fine-tuning

SAM2 这类大模型迁移到遥感变化检测时，”只解冻最后 stage”是最常见的折中：比 linear probing 效果好，又比全微调省显存、少过拟合。这也正好引出下一节要讲的第三个选项——Adapter：不改主干主体，只在主干旁边挂小模块。

八、运行前检查清单

  • 已安装 torch、torchvision、timm，能正常 import
  • 首次运行允许联网（CIFAR-10 + 预训练权重）
  • 输入已 Resize 到 224×224，输出 logits 形状 [B, 10]
  • 线性探测时新分类头 requires_grad=True
  • 训练循环包含 zero_grad / backward / step
  • 正式实验要划分验证集或留出测试集，别只看训练 loss
