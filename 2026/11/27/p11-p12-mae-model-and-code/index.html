二、问题起点：掩码重建为什么值得再做一次

BEiT（P6）已经验证了「mask 掉一部分 patch，让模型把被 mask 的内容预测回来」可以训出好表征，但它的预测目标是 dVAE 离散 token，中间多了一个需要预先训练的词表。MAE 的出发点是把这个中间层拿掉：直接回归像素。

问题在于，像素级重建有一个天然的陷阱——如果掩码率很低，模型完全可以「抄近路」：相邻 patch 高度冗余，看一眼邻居就能把空白填个八九不离十，网络学不到语义。所以 MAE 的三条设计其实是互相咬合的一组取舍：

设计选择 具体做法 解决什么问题
极高掩码率 随机 mask 掉 75% 的 patch（196 个里 mask 147 个） 让重建任务足够难——剩下的 25% 无法靠局部插值蒙对，必须理解全局语义
非对称编解码器 encoder 只看可见 patch（49 个 token），decoder 才处理全部 196 个 token 编码器只需处理 1/4 的 token，训练速度提上来了；同时 encoder 不必为「空位」浪费容量
损失只在 mask 上算 MSE 只对 147 个被 mask 的 patch 求和平均 迫使模型学「从上下文推缺失」，而不是学恒等映射

讲师在 P11 反复强调的一点是：这三条不是并列的独立技巧，而是**「掩码率上去了，才敢只让 encoder 看可见 patch」**——正因为 25% 的可见 patch 已经足够提供全局结构信息，编码器才不需要看到 mask token。

三、MAE 的四步流水线

3.1 第一步：切 patch（patchify）

输入图像 $x\in\mathbb{R}^{3\times 224\times 224}$，按 16×16 的 patch 切分，patch 数量为

$$N=\frac{H}{P}\times\frac{W}{P}=\frac{224}{16}\times\frac{224}{16}=14\times14=196$$

每个 patch 拉平成 3×16×16=768 维向量，再线性映射到 embedding 维度 768（ViT-Base 的宽度）。这一步在实现上就是一个 kernel=16, stride=16 的卷积层。

3.2 第二步：随机掩码

从 196 个下标里随机选 147 个置为「被 mask」，保留 49 个可见 patch：

$$n_{\text{mask}}=\lfloor r\cdot N\rfloor=\lfloor 0.75\times 196\rfloor=147,\qquad n_{\text{vis}}=N-n_{\text{mask}}=49$$

注意这里是无放回随机采样（torch.randperm），每个 patch 被选中的概率相同，与位置无关。这一点和「结构化掩码」（如按块状遮挡）不同，MAE 的消融实验显示纯随机就够了。

3.3 第三步：非对称的 encoder–decoder

这一步是 MAE 相对 BEiT 最大的改动，也是讲师在 P11 花最多时间解释的部分（P11_200、P11_260）：

  • Encoder（重）：ViT-Base 结构，12 层 Transformer block，宽度 768，12 个注意力头。只吃 49 个可见 token，不走 mask token。
  • Decoder（轻）：先做一次线性投影升维，再依次是 LayerNorm → 激活函数（GELU）→ 线性层，把 49 个可见 token 加上 147 个 mask token 一起处理，输出 196 个重建 patch。
$$\{z_i\}_{i\in\mathcal{V}}=\text{Encoder}\big(\{x_i+p_i\}_{i\in\mathcal{V}}\big),\qquad \hat{x}=\text{Decoder}\big(\{z_i\}_{i\in\mathcal{V}}\cup\{m\}_{i\in\mathcal{M}}\big)$$

其中 $\mathcal{V}$ 是可见集合、$\mathcal{M}$ 是被掩码集合、$p_i$ 是位置编码、$m$ 是可学习的共享 mask token（所有被掩码位置共用同一个向量）。

为什么 encoder 可以「跳着」处理？因为 ViT 的注意力本身是置换不变的，位置信息靠位置编码注入。可见 token 的下标不必是连续的，把它们按原顺序收集起来送进 encoder 即可——这也是为什么 P12 的代码里要先算 mask 下标、再做 gather。

论文补充：论文原版 decoder 是 8 层、宽度 512、16 头的浅层 Transformer（不再区分注意力头数的小细节随版本略有差别），训练 1600 epoch，encoder 与 decoder 的宽度不对称带来的加速非常显著——MAE 的预训练速度比 BEiT 快 3 倍以上，主要就来自「encoder 只看 25% token」。

3.4 第四步：损失只在 mask 上算，下游只用 encoder

$$\mathcal{L}=\frac{1}{|\mathcal{M}|}\sum_{i\in\mathcal{M}}\big\|\hat{x}_i-x_i\big\|_2^2$$

预训练结束后，decoder 整块丢弃，只留 encoder 作为视觉骨干，接到检测/分割头上下游微调。这是 MAE 与「图像自编码器」的关键区别：decoder 只是训练期的脚手架。

四、P11 给出的核心结论

结论 讲师原话要点 意义
掩码率 75% 是最优区间 掩码率从 0.5 提到 0.75，线性探测与微调精度同时上升 高掩码率是 MAE 能成立的前提，不是可有可无的超参
重建结果偏模糊 重建出来的图像明显比原图「糊」，高频细节丢失 说明模型学的是语义/结构而非像素细节，这恰好是下游需要的
检测分割超越有监督预训练 在 COCO 检测、ADE20K 分割上超过用 ImageNet 标签预训练的 ViT 打破「自监督线性探测强、下游微调弱」的旧印象
可扩展性好 从 ViT-B 到 ViT-H（632M），精度随模型变大持续提升 这条后来成为「视觉大模型」的标配叙事

讲师给的是「简化版」实现——刻意砍掉了论文里的工程细节（混合精度、学习率 warmup、随机裁剪增强、分层学习率等），只留下网络结构的骨架。下面按 __init__ → forward → loss 三段拆解，代码块为按讲师口述逻辑整理的等价可运行版本。

位置编码 nn.Parameter(1, 196, 768)，可学习 0.15M

5.2 forward：一次完整的前向

三个容易写错的地方，讲师在 P12 里都特意点了一句：

  1. 位置编码要广播：pos_embed 的形状是 (1, N, D)，而 patch 特征是 (B, N, D)，必须 repeat 或依赖广播把 batch 维对上；
  2. mask 是「打乱后的前 49 个保留」：先 randperm 出乱序下标，取前 len_keep 个作为保留（注意是保留，不是丢弃），这和「取前 147 个作为 mask」是同一件事的两种写法；
  3. mask token 拼回后必须还原顺序：encoder 输出的是「可见 token 在前、mask token 在后」的乱序排列，要用 ids_restore 做一次反排列，才能和原始 patch 的顺序对齐算 loss。

六、与 BEiT（P6）的对比

维度 BEiT（P6） MAE（P11）
预测目标 dVAE 离散视觉 token 原始像素 patch
需要额外模型 是，需先训 dVAE 词表 否，端到端

一句话总结两者的关系：BEiT 证明「掩码预测」这条路可行，MAE 证明「这条路根本不需要语言模型的词表，像素就够了，而且可以更狠」。

七、实践提示

  1. 掩码率不要低于 0.6：低于这个值重建任务过于简单，模型退化成低通滤波器，下游微调精度掉得很快。
  2. 先小分辨率调通再放量：简化版用 224×224 单尺度，实际预训练常见 224 预训练 → 448 微调。
  3. decoder 一定丢弃：微调时只 model.blocks + model.norm 接下游头，decoder 和 mask_token 都不进下游。
  4. 位置编码两种都行：可学习位置编码参数少、实现简单（讲师选它）；sin-cos 在分辨率变化时更稳（可插值）。
  5. batch 内掩码相互独立：代码里 noise 是 (B, N)，每个样本各打各的，不能共用同一套下标。
