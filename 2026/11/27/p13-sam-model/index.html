二、为什么 SAM 出现在「视觉大模型」这一章

讲师开场先回答了一个可能的疑问：前面两讲都是自监督，SAM 是有监督的，凭什么放在同一章？他的回答有三层：

  1. 「大模型」的判定标准不是训练方式，而是「模型足够大 + 数据量足够多」；
  2. SAM 的核心贡献是用一套方法自动造出了海量带标签数据（数据引擎 + SA-1B），把「标注成本」这个分割任务的老大难问题绕开了；
  3. 它的 image encoder 直接用的是上一讲的 MAE，prompt 的文本分支直接用的是下一章的 CLIP 文本编码器——它是「拼装式大模型」的典型样本：别人训好的重编码器不动，只训轻量的下游模块。

一句话概括它的野心：从「分割某个类别」变成「分割一切」，从「固定任务」变成「按提示分割」。

三、SAM 的三要素

论文把 SAM 拆成三个互相咬合的部分，讲师在结构图上依次讲解（P13_600、P13_780）：

要素 内容 讲师强调的点
Task：可提示分割 输入 = 图像 + prompt（点/框/涂鸦 mask/文本），输出 = 与 prompt 对应的 mask 把语义分割、实例分割、前景分割等不同层级的分割统一成同一个「提示→掩码」任务，这正是「分割一切」的来源
Model：三组件架构 image encoder（MAE-ViT）+ prompt encoder + lightweight mask decoder 前两个编码器几乎不训，只训 decoder；encoder 重、decoder 轻
Data：数据引擎 + SA-1B 三阶段自动标注流程，最终 1100 万张图、11 亿个 mask 模型能力与数据规模互相促进的「飞轮」

3.1 Task：prompt 是什么

prompt 在视觉里的含义和 NLP 一致——模型输入之外，你额外提供的引导信息。SAM 定义了四类：

  1. 点（point）：在目标上点一下（正点）或点一下背景（负点），模型把该点所在的物体抠出来；
  2. 框（bounding box）：给一个矩形，模型分割框内主体，类似检测框转分割；
  3. 涂鸦 mask（mask prompt）：直接在目标上涂几笔，模型补全边缘——讲师的原话类比是「美图秀秀的智能抠图」；
  4. 文本（text）：用一句话描述要分割什么（如「黑耳朵的猫」）。

讲师判断：文本 prompt 在论文里有，但官方 demo 和开源代码都没有放出这一类接口，因此「目前效果可能还不够好、稳定性不够鲁棒」。这是他的推断，不是论文结论——但下一章 CLIP 正是为这类「文本理解图像」的能力打的地基。

3.2 Model：三个组件各自做什么

① Image encoder：直接拿 MAE 预训练的 ViT（论文为 ViT-H/16，输入 1024×1024，输出 64×64 的特征图）。不参与训练——这一层不动，是整个架构能「大」的前提。

② Prompt encoder：按 prompt 类型分流编码：

prompt 类型 编码方式
点 / 框 坐标→位置编码（与 ViT 输入层的位置编码同思路），再加类型 embedding 区分「正点/负点/框角点」
涂鸦 mask 小卷积网络降采样后与图像特征对齐
文本 直接调用预训练的 CLIP 文本编码器，不另行训练

③ Mask decoder：轻量 Transformer decoder，融合两路特征后输出 mask。注意力分成两部分：

$$\underbrace{\text{Self-Attn}(\text{prompt tokens})}_{\text{prompt 之间互相感知}}\;\rightarrow\;\underbrace{\text{Cross-Attn}(Q=\text{prompt},\;K,V=\text{image tokens})}_{\text{prompt 去图像里找对应区域}}$$

即：Q 来自 prompt token，K/V 来自图像特征 token；本质上是「把两类特征拼起来做 token 级的注意力融合」，与 P10 讲 DINO 的 cross-attention、以及 P18 的 GLIP 融合层是同一个套路。encoder 重、decoder 轻，与 MAE 的非对称设计一模一样，这也是讲师反复强调的「大模型范式」。

3.3 Data：数据引擎三阶段（论文补充）

阶段 做法 产出量级
Assisted-manual 标注员用 SAM 辅助点选，模型即时给 mask，人只做修正 约 12 万 mask / 430 万图的一部分
Semi-automatic 让模型先自动分割高置信区域，人只补漏标 增加约 590 万 mask / 1020 万图
Fully automatic 规则化网格点提示 + 多尺度裁剪，模型全自动产出 mask，再用 IoU/稳定性规则过滤 SA-1B：1100 万图、11 亿 mask

数据引擎的逻辑是**「模型帮人标注 → 数据变多 → 模型变强 → 标注更快」**的闭环，这也是讲师用来解释「它为什么能叫大模型」的核心论据。

四、损失函数

SAM 的 mask 预测用 focal loss + dice loss 的加权和（论文补充，权重 20:1）：

$$\mathcal{L}=\lambda_{f}\mathcal{L}_{\text{focal}}+\lambda_{d}\mathcal{L}_{\text{dice}},\qquad \lambda_{f}=20,\;\lambda_{d}=1$$
$$\mathcal{L}_{\text{dice}}=1-\frac{2\sum_i p_i g_i}{\sum_i p_i^{2}+\sum_i g_i^{2}}$$
  • focal loss 处理「前景像素远少于背景」的类别不平衡，让模型聚焦难分的边界像素；
  • dice loss 直接优化预测 mask 与真值 mask 的重叠度，对前景占比极小的目标不敏感退化。

两者组合是分割任务的常规搭配，SAM 并没有在损失上做创新——它的创新在任务定义与数据规模。

五、实验与结论

讲师带着看了三组结果（P13_700）：

实验 设置 结论
Point-to-mask（23 个数据集） 只给一个点，比较 IoU 在多数数据集上超过 RITM 等交互式分割方法
Zero-shot 检测（转成检测框） SAM 输出 mask → 取外接框，与有监督检测器对比 COCO 上的「匹配精度」看似不高，但人工评估显示实际分割/框质量更好——讲师指出这是 COCO 标注本身不准确导致的指标失真
下游零样本迁移 直接拿 SAM 分割结果当下游输入 分割是零样本的，不需要为目标数据集训练

局限（讲师明确提到，且不自夸）：SAM 在检测任务上与传统有监督检测器仍有差距；它统一的是「分割」这一个领域，不是整个 CV。所谓「CV 不再存在」是自媒体的夸张说法。

六、本章（第三章）总结：三个视觉基础模型的关系

模型 训练方式 核心思想 在本课程中的角色
ViT（P7） 有监督 把图像切成 patch 当 token，Transformer 直接吃 一切后续模型的容器/骨干
DINO（P9、P10） 自监督 学生-教师自蒸馏，无需负样本 证明自监督 ViT 可以超越有监督
MAE（P11、P12） 自监督 75% 掩码 + 非对称编解码 + 像素重建 提供最强、最快的预训练范式
SAM（P13） 有监督（数据自动生成） prompt 化任务 + 数据引擎 + 只训轻量 decoder 展示「大模型拼装」的工程范式

讲师用一句话收束第三章：大模型不等于自监督；只要有足够大的模型和数据，并且能用少量可训练参数把预训练模块接起来，就落在这一章的范围里。

七、实践提示

  1. 想在 SAM 上做二次开发，改的是 decoder：image encoder 冻结、prompt encoder 少量参数，decoder 才是可训部分；
  2. 点提示的正负搭配很关键：只给一个正点常常会把相邻同类物体一起带进来，加几个负点能明显收敛；
  3. 框提示最稳：如果已有检测结果，直接传框比传点更可靠，这也是「检测→分割」流水线的常见用法；
  4. 别把它当通用检测器：mask 外接框在密集场景下会粘连，检测精度不如专用检测器；
  5. 文本 prompt 分支慎用：官方实现未开放，需要自己接 CLIP 文本编码器并微调。
