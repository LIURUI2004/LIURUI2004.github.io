4.6 Flamingo 模型

2026-11-27 #多模态大模型#Flamingo#视觉语言模型#In-Context Learning

一、视频信息与定位

项目 内容
稿件 BV1E9U8BBEvZ（B站强推！全网最全最详细的多模态大模型教程）
分P P19（4.6 Flamingo 模型），时长 547 秒（9:08）
关键论文 Alayrac J B, Donahue J, Luc P, et al. Flamingo: a Visual Language Model for Few-Shot Learning. NeurIPS 2022（DeepMind）
本节定位 P15 分类里的类型 D（适配 LLM）的第一个代表。CLIP 解决「图文对齐」，GLIP 解决「区域-词对齐」，Flamingo 解决的是「怎么把图像塞进一个已经训好的大语言模型，同时不破坏它的语言能力」——这是多模态大模型最核心的工程问题，LLaVA（P20）用的是它的简化版答案。

素材来源说明

  • AI 字幕原文：249 条，547 秒；
  • 定点截图：9 张（P19_10~`P19_500`）；
  • 论文补充项（参数量细节、训练数据 M3W/LTIP/VTP 的规模、冻结策略）均已标注，讲师口述「80B」指总参数量。

二、动机：为什么不能「直接把图喂给 LLM」

最朴素的想法是：把图像 patch 当成 token，和文本 token 拼在一起，端到端训练。但这条路在 2022 年行不通，原因有两个：

  1. 算不起：70B 级的 LLM，端到端训练要把视觉数据灌进整个网络，梯度回传贯穿全部层，成本是天文数字；
  2. 会遗忘：若放开 LLM 的参数去适配图像，模型的语言能力会退化（灾难性遗忘），而语言能力恰恰是它最值钱的部分。

Flamingo 的答案是：LLM 完全冻结，一点不动；在旁边加「外挂模块」把视觉信息注入进去。整个模型被誉为「用最少的可训练参数，给最大的模型装上了眼睛」。

三、三个组件

3.1 视觉编码器（冻结）

用预训练的 CLIP ViT（P16 的产物）作为图像塔，输出网格状的视觉特征。讲师在这里呼应了上一节：CLIP 训练出的表征之所以值钱，就是因为它能被这么多下游模型直接复用。

3.2 Perceiver Resampler：把变长特征压成固定长度

这是 Flamingo 的第一个关键设计。问题在于：图像数量可变、分辨率可变，视觉 token 数就会变（一张图 100 个、四张图 400 个）；而 LLM 的上下文长度有限，直接拼进去既浪费也不稳定。

Perceiver Resampler 用一组可学习的 latent 查询向量去「读」视觉特征：

无论输入多少张图、多少 patch，输出永远是 个 token（论文补充：n=64）。讲师把这个模块的作用总结成一句话：「不管你有多少图，我都压成固定长度的视觉 token」——这既是效率手段，也是让多图输入可行的前提。

3.3 门控交叉注意力层（Gated Cross-Attention Dense）

这是 Flamingo 的核心创新。在冻结 LLM 的每若干层之间（论文补充：每 4 层插一个），插入一个 GATED XATTN-DENSE 模块，让文本 token 去「查询」视觉 token：

两个工程细节必须记住（讲师在 P19_60 特意指向了这块）：

  1. tanh 门控 初始化为 0：训练第一步 ，整个模块相当于恒等映射，模型输出与原 LLM 完全一致。随着训练，门控慢慢打开，视觉信息被「渐进注入」，避免一开始就破坏语言能力；
  2. 原 LLM 的每一层参数一个都不改：注意力、FFN、LayerNorm 全部冻结，只训 Resampler 与新插入的交叉注意力层。

这就是「冻结 + 外挂」的具体实现，也是它能用很少的可训参数搞定 70B 模型的原因。

四、图像在文本里怎么「占位」

Flamingo 在文本序列中插入特殊的 <image> token 标记图像出现的位置（讲师在字幕里专门讲了这个机制）。

处理流程是：

  1. 文本先按 <image> 切段，<image> 位置留一个占位 token；
  2. 该位置对应的视觉 token（Resampler 输出的 64 个）通过交叉注意力注入；
  3. 于是模型可以处理「图文交错」的任意序列——这使得多图、多轮、few-shot 示例都在同一个序列里完成。

这个设计带来的直接能力是 in-context few-shot learning：给两张「图 + 问 + 答」的示例，再给一张新图提问，模型就能模仿示例的格式作答，不需要任何梯度更新（P19_450）。

五、训练数据与规模

数据 内容 规模（论文补充）
M3W（MultiModal MassiveWeb） 网页图文交错序列 约 4300 万网页
LTIP（Long Text & Image Pairs） 长文本 + 图像对 约 3.12 亿
VTP（Video & Text Pairs） 视频帧 + 文本 约 2700 万

总计约 80B 参数（Chinchilla 70B + 视觉侧与新模块约 10B），其中可训练部分仅约 10B 量级——即只有 Resampler 和 gated cross-attn 参与训练。这组数字正是「冻结大模型 + 训练小模块」这条路线最有力的证明。

六、能力与局限

能力 说明
多图推理 一次输入多张图，能做比较（「这两张图里的动物是同一只吗」）
Few-shot 快速适应 通过示例提示即可切换到新任务，无需微调
视频理解 视频拆成帧，按多图方式处理（P19_120 提到）
开放问答 看图回答开放式自然语言问题

局限（讲师明确指出 + 后续研究共识）：

  1. 不擅长需要精确定位的任务：输出是自由文本，无法给出可靠的像素级坐标或 mask；
  2. 不能做细粒度分类：CLIP 塔的整图表示决定了它对小目标、密集场景的判别力有限；
  3. 幻觉：继承自 LLM 的「编造」倾向，看图说话时会补出图中不存在的内容；
  4. 训练成本仍高：虽然可训参数少，但前向仍要跑 70B 模型，推理成本极高。

七、在技术谱系里的位置

Flamingo 与 LLaVA 的关系可以这样理解：

  • 相同：都是「冻结或半冻结 LLM，只训连接模块」，都把视觉 token 注入 LLM；
  • 不同：Flamingo 用交叉注意力注入（视觉信息在每层都能被查询），LLaVA 用前缀拼接注入（视觉 token 直接作为文本前缀拼进输入序列），后者实现简单得多，代价是视觉信息只能通过自注意力的上下文间接影响。

讲师在 P19_500 的收尾观点是：从 Flamingo 到 LLaVA，架构在变简单——因为大家发现「大模型本身足够强，连接方式不必那么精巧，数据和指令质量更重要」。

八、本篇要点核对清单

  • 动机：端到端训练 70B 模型算不起，且会遗忘语言能力 → 冻结 LLM + 外挂模块
  • 三组件：CLIP 视觉编码器（冻结）、Perceiver Resampler（变长→固定 n 个 token）、门控交叉注意力层
  • tanh 门控初始化为 0 的意义（训练起点等价于原 LLM）
  • <image> 特殊 token 标记位置，支持交错序列、多图、多轮
  • few-shot in-context learning 无需梯度更新
  • 数据规模（M3W / LTIP / VTP）与「80B 总参数、约 10B 可训」
  • 四条局限，以及它与 LLaVA 在注入方式上的根本差异
