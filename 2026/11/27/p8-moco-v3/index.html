一、视频信息与定位

二、先建立一个正确预期：v1 → v2 → v3 是”微调”，不是”重做”

这一节开场，讲师先给了一个容易被忽略的判断，值得放在最前面：

“虽然说我们的 MoCo 从 V1 到 V2 再到 V3，但它其实每一个版本的改进都非常小，都是很细节方面的东西，它在本质上面呢并没有发生很大的变化。”（00:33–00:44）

这句话是理解整节的钥匙。MoCo 三代共享同一个骨架：

三代的差异，全部落在这个骨架的三个”参数位”上：骨干用什么、负样本从哪来、损失算几遍。下面逐层展开。

三、先把 v2 补完，v3 才有落脚点

3.1 v2 的两处改动：来自 SimCLR 的两个”便宜又好用”的点

讲师原话：

“在 MoCo v2 当中呢，他们就把 SimCLR 里面的两个提点的方式给引入了进来。第一个呢是使用更多的这个数据增强，第二个呢把 SimCLR 当中的我们前面所说的两个映射层给加入了进来。”（00:52–01:05）

这两点分别是：

（1）更强的数据增强。 SimCLR（P3）证明，对比学习的效果高度依赖增强强度——裁剪、颜色抖动、以及 SimCLR 新引入的 高斯模糊（Gaussian blur）。MoCo v1 的增强相对温和，v2 直接把 SimCLR 的增强组合搬过来。原因很直观：对比学习的监督信号是”这两张图是同一张”，如果增强太弱，两张图几乎一样，网络用颜色直方图这种廉价特征就能把正样本配对成功，学不到语义。

（2）加一层 MLP 投影头（两层映射层）。 讲师把细节讲得很清楚：

“它在我们每次得到的这个特征之后呢，它会进行一个 MLP，然后呢把经过 MLP 之后的两个这个特征呢去计算对比的 loss。我们在下游任务当中呢，我们只会使用 MLP 之前的这个来做下游的任务。”（01:08–01:20）

也就是说数据流是：

注意这里的**”用 h 不用 z”**是 SimCLR 提出的经验结论：投影头的作用是给对比损失提供一块”可牺牲的表达空间”，让主干特征保留更多与任务相关的信息，而不是被对比目标”压扁”成只适合算相似度的形态。MoCo v2 引入这一层，几乎零成本地涨点。

一句话记忆：v1 → v2 = 增强变强 + 多一个投影头，主干和队列机制完全没动。

四、v3 改动一：把 ResNet 换成 ViT

4.1 讲师怎么说的

“MoCo v2 呢它还是基于 ResNet 这种结构，但是 MoCo v3 呢他就开始使用了 ViT 的这种结构。也因此我们现在经常会在开源代码都能看到，它使用 ViT 模型，它可能并不是原版的 ViT，它会叫做 vision transformer MoCo。那这个呢其实也就是我们将 ViT 模型和自监督的 MoCo 进行结合的一样的这样的一种网络结构。”（00:12–00:33）

图 1：P8_25.png（00:25 附近）。PPT 标题为「MoCo v3」，副标题「基于 ViT 架构的自监督学习」，画面右侧缩略给出上一讲 MoCo v1 的原始结构（双编码器 + 队列），用于做前后对照。这是本节的总览页。

4.2 为什么换 ViT：三层理由

讲师只说是”换成 ViT”，没有展开动机，这里补全（论文补充）：

  1. 容量可扩展性。 ResNet 的规模被”深度 + 宽度”卡住，继续加深会遇到优化困难和收益饱和；ViT 的参数与层数、宽度呈干净的线性关系（P7 已算过：86M / 307M / 632M），能顺着 NLP 的 scaling law 一路放大。对比学习恰好是”数据越多越受益”的方法，两者天然匹配。
  2. 没有 BatchNorm 的”偷懒通道”。 这是 MoCo v3 论文真正的出发点。ResNet 里有 BN，BN 在训练时会在 batch 内部泄漏样本间信息——对 q 分支尤其严重：同一 batch 里的正样本和负样本在 BN 层就已经互相”看见”了，对比任务因此变得太容易，学到的特征虚高。ViT 用 LayerNorm，只依赖单个样本自身，这个泄漏通道被彻底切断。代价是：没有 BN 也失去了它带来的数值稳定性，这正是第七节要处理的麻烦。
  3. 架构统一。 换掉骨干后，MoCo 的公式一个字都不用改：q = f_q(x1)、k = f_k(x2)、f_k ← EMA(f_q)，$f$ 是 ViT 还是 ResNet 只是实现细节。这也是讲师强调”本质没变”的原因。

4.3 一个必须记住的对应关系

MoCo 概念 ViT 里对应什么
Encoder $f_q$ 完整 ViT-B/16（PatchEmbed + 12 层 Encoder），输出取 [CLS] 位
Momentum Encoder $f_k$ 结构相同、参数由 $f_q$ 的 EMA 得到，不参与反向传播
输出维度 $C$ 768（ViT-B），投影头后 256（MoCo v3 默认）
队列 / 负样本 v3 中取消，改用 batch 内样本

对照 P7 的知识：ViT 的 [CLS] 位向量（768 维）就是这里的 q 和 k 的来源。P7 讲的”CLS Token 把整张图的摘要托付给一个位置”，在这里落地为”对比学习的锚点”。

4.4 换成 ViT 后，训练变难了（伏笔）

字幕没有展开，但要在心里留一条线：ResNet + BN 的 MoCo v1/v2 训得很稳，ViT + LN 的 MoCo v3 则频繁出现 loss 尖刺（loss spike）甚至直接发散。原因有三：

  • 没有 BN，激活值的尺度不受约束，深层容易数值爆炸；
  • 自监督目标本身比监督目标更”不稳”——目标函数随特征一同移动，是一个移动靶；
  • 大 batch（4096）下，优化器步长很大，小的扰动被放大。

这条伏笔在第七节收拢，那里的三个技巧就是专门治这个病的。

五、v3 改动二：删掉 Memory Bank，用大 batch 顶上来

5.1 讲师原话（这是本节最核心的一段）

“首先呢是他不再使用内存银行的这种设计了……作者发现只要我的 batch size 足够大，那里面的负样本它就可以有很多。所以说他直接就选了一个很大的 batch，比如说我直接选 4096 那么大的一个 batch。那之前我们在讲解 MoCo 的代码的时候呢，我们在这个 memory bank 其实设的也是 4096 的这样的一个大小。那如果说我现在直接把 batch 取成 4096，那我就不需要使用这个内存银行，我同样可以获得一个非常大的负样本。”（01:36–02:09）

图 2：P8_90.png（01:30 附近）。PPT 副标题直接写着「MoCo v3: 1) 取消内存银行，由大 batch 代替」——这是三点改动中的第一点，页面为小节标题式，细则由讲师口述。

5.2 核心逻辑：负样本数量 K 与 batch size B 是同一个角色

MoCo v1 的设计动机是”显存装不下大 batch，那我就用一条队列把历史上算过的 key 存起来当负样本”。也就是说：队列是对大 batch 的一次”显存借用”。

v3 的观察是反向的：既然队列的作用只是”凑够足够多的负样本”，那么在硬件允许时，直接买（而不是借）——把 batch 开大，batch 内就是天然的负样本池：

方案 负样本来源 默认数量 显存占用 样本”新鲜度”
v1/v2 队列 过去若干 step 的 key 缓存 65536（v1）/ 4096（简化版代码） 稳态，不随 batch 增长 陈旧（可差几十上百 step）
v3 大 batch 当前 step 同 batch 内的 key 4096（每卡 1024 × 4 卡） 随 batch 线性增长 最新鲜，与 q 同一步

5.3 两种负样本的真实差异（不要只看数量）

很多人以为”队列 4096 = batch 4096，所以等价”，其实不然，严格比较要分三点（论文补充 + 原理推演）：

  1. 一致性（consistency）。 队列里的 key 是旧参数算出来的，与当前 k 的分布有偏移，属于”过时负样本”；batch 内的 key 全部由同一个 momentum encoder 在当前步算出，分布完全一致。这正是 MoCo v1 引入动量编码器要缓解的问题——用大 batch 时，这个问题从源头消失了，所以 v3 里动量系数可以放松（默认 0.99 甚至不依赖长队列）。
  2. 新鲜度 vs 多样性。 队列能以很小的显存代价堆到几十万负样本；batch 4096 只能有 4096 个。所以在同等显存下，队列的负样本数量上限更高——这是 v1/v2 在 ResNet 时代仍然占优的原因。
  3. 通信成本。 batch 4096 意味着必须跨卡同步，每步都要做 all-gather；队列则可以在单卡内维护。所以 MoCo v3 是”用通信换简洁”。

由此可以理解讲师那句”本质没变”——队列的删除不是理念进步，而是硬件条件变化后的工程取舍。如果只有单卡 24G，MoCo v3 的大 batch 方案根本跑不起来。

5.4 与之配套的标签构造变化

队列方案里，loss 的 logits 是 [B, K+1]（1 个正样本 + K 个队列负样本），标签恒为 0（正样本在 index 0）。参考 P5 代码里那句 labels = torch.zeros(logits.shape[0], dtype=torch.long)。

去掉队列后变成标准的 batch 内对比：[B, B] 的相似度矩阵，正样本落在对角线上，标签是 arange(B)。这是 P5 与 P8 在代码层面最直观的差别。

图 3：P8_125.png（02:05 附近）。PPT 副标题「MoCo v3: 1) 取消内存银行，由大 batch 代替」，同一小节的延续页，讲师在此处对比两种负样本来源的得失。

六、v3 改动三：把单向损失改成双向（对称）损失

6.1 讲师原话

“第二个优化呢是在 loss 这边，MoCo v3 呢它开始采用一种双向的一个 loss……我们有一个 query，还有一个 key……我给他写成 X1……这个 key 呢我们现在只是考虑它的正样本，不考虑他那么多负样本，我们给他写成 X2。那么 X1 和 X2 呢是经过数据增强之后得到的图像，所以说他们是一对正样本。”（02:12–02:40）

“既然这两张图像都是通过增强之后得到的，那么他们并没有贵贱之分，所以我也可以把这里的 X2 当做 Q，而 X1 当做 K 也是 OK 的。”（02:58–03:11）

6.2 先写清单向损失（v1/v2 的形态）

给一个 batch，$x_1, x_2$ 是同一张图两种增强视图。v1/v2 只算”以 $q_1$ 为锚点”的那一半：

$$ \mathcal{L}_{q_1} = -\log \frac{\exp\left(q_1 \cdot k_2^{+} / \tau\right)}{\exp\left(q_1 \cdot k_2^{+} / \tau\right) + \sum_{i=1}^{K} \exp\left(q_1 \cdot k_i^{-} / \tau\right)} $$
  • $q_1 = f_q(x_1)$，带梯度；
  • $k_2^{+} = f_k(x_2)$，由动量编码器给出，无梯度；
  • $k_i^{-}$：v1/v2 是队列里的历史 key，v3 是 batch 内的其他 key；
  • $\tau$：温度系数，MoCo 系列默认 0.2（video P3 已讲温度的作用）。

6.3 再看双向损失

$$ \mathcal{L} = \underbrace{\mathcal{L}\left(q_1, k_2\right)}_{\text{方向 A}} + \underbrace{\mathcal{L}\left(q_2, k_1\right)}_{\text{方向 B}} $$

统一写成：

$$ \mathcal{L}\left(q, k^{+}\right) = -\log \frac{\exp\left(q \cdot k^{+} / \tau\right)}{\sum_{j=1}^{B} \exp\left(q \cdot k_j / \tau\right)} $$

其中分母遍历当前 batch 全部 $B$ 个 key（含正样本自身），$k_j = f_k(x_2^{(j)})$。

对应关系（必须记牢，否则写代码会错位）：

方向 送进 Encoder（带梯度） 送进 Momentum Encoder（无梯度） 得到
A $x_1$ $x_2$ $q_1$ 对 $k_2$
B $x_2$ $x_1$ $q_2$ 对 $k_1$

注意方向 B 里，$x_2$ 走的是带梯度的 encoder，$x_1$ 走的是动量 encoder——不是把 $q_1$、$k_2$ 简单互换，而是重新跑一遍前向。这是”双向”最容易写错的地方。

图 4：P8_170.png（02:50 附近）。PPT 副标题「MoCo v3: 2) 双向的对比 loss」，画面上半部分是 MoCo v1 的单向结构，下半部分是 v3 的双向结构，直观对比”算一遍”和”算两遍”的差别。

图 5：P8_200.png（03:20 附近）。同一小节延续页，展示 $(x_1,x_2)$ 经两路编码器得到 $(q_1,k_1)$、$(q_2,k_2)$ 后，两组正样本相似度如何合成最终损失。

6.4 为什么要对称：三个理由

  1. 两张增强图地位对等。 讲师的原话就是”没有贵贱之分”。既然增强是随机采样，凭什么让 $x_1$ 当 query、$x_2$ 只能当 key？对称之后，对增强分布的期望被利用得更充分——每个 batch 实际上产生了 $2B$ 个”锚点样本”而非 $B$ 个，等于免费把有效 batch 翻倍。
  2. 梯度更均衡。 单向损失下，encoder 只在”$x_1$ 作输入”这一种角色上收梯度；双向之后，两类视图都既当锚点又当目标，主干学到的表示不会偏向某种增强模式。
  3. 与 SimCLR 收敛到同一形态。 有意思的是，SimCLR（P3）的 NT-Xent 本来就是对称的——它没有队列，天然就要对 $2N$ 个视图两两算。MoCo v1 为了省算力（队列方案下算两遍不划算）才只算一半。v3 取消队列后，算两遍的边际成本很低，于是把对称性”还”了回来。所以严格说，这不是新发明，而是”条件允许后回归最优形态”。

6.5 梯度走向（讲师特别强调的一句）

“和 V1 一样，我们作为 query 的 encoder，他是直接参与这个梯度的反向传播的，也就是这个 BP，而这个 momentum encoder 呢，它的梯度呢是通过动量的更新公式来进行一个优化的。”（04:21–04:35）

$$ \theta_k \leftarrow m\,\theta_k + (1-m)\,\theta_q, \qquad m = 0.99 $$

这一句对应 P5 代码里训练循环末尾那行 EMA 更新。两个方向共用同一个 $f_q$ 和同一个 $f_k$：方向 A 与方向 B 的梯度都累加到 $f_q$ 上，然后每步一次 EMA 同步到 $f_k$。不要理解成”两个 encoder 各训一次”。

七、真正的工程核心：训练稳定性

本节视频只有 4 分 35 秒，讲师把大部分时间给了三点改动，稳定性部分讲得很轻。但 MoCo v3 论文的标题就是 An Empirical Study of Training Self-Supervised Vision Transformers——它的主要贡献其实就是这张”怎么把 ViT 自监督训稳”的药方。这里按论文补齐（标注为论文补充，非视频画面）。

图 6：P8_240.png（04:00 附近）。本节收尾的稳定性小节页，对应论文中”避免训练崩溃”的一组技巧。

7.1 症状：loss spike

现象是：训练前期一切正常，某个 step 突然 loss 跳升，之后特征坍缩（所有图像输出几乎相同向量），线性探测精度永久掉下去。论文的观察是——崩溃往往发生在训练早期，且与 patch projection 层（即 ViT 最前面那个 stride=16 的卷积）的梯度异常直接相关。

7.2 药方一：冻结 patch embedding（最有效、最反直觉）

做法：训练最开始若干 epoch（论文用 10 epoch 左右，占总训练 300 epoch 的 3%），把 PatchEmbed 那一层的参数冻结，不接收梯度，也不被优化器更新；之后解冻、正常训练。

为什么有效：PatchEmbed 是整座网络的入口，它的输出要经过 12 层 Transformer 放大。这一层在初始阶段梯度噪声极大，一旦它的权重被推向一个坏方向，后面所有层都在学”垃圾输入”。冻结它相当于给入口装了一个稳压器，让主干先用固定的”词表”把注意力与 MLP 学起来，等梯度尺度稳定后再放开。

代价：几乎为零。这一层只有 $16\times16\times3\times768 \approx 590K$ 参数（占 ViT-B 的 0.7%），冻结它不影响容量。

这一条与 P7 结尾那句伏笔正好对上：“ViT 没有 BN，自监督训 ViT 会崩，这正是冻结 patch embedding 要解决的问题。”

7.3 药方二：梯度裁剪

大 batch 下单步梯度的 L2 范数可能突增两个数量级，裁剪把步长钳住。论文中给出的做法是按”梯度范数 / 参数范数”的比例裁剪（ratio clip），比固定阈值更自适应。

7.4 药方三：随机深度 + Layer Scale

  • Stochastic Depth（DropPath）：训练时随机整层跳过（对 ViT-B 用 0.1 左右），减少层间共适应，等效于集成。
  • LayerScale：在每个残差分支出口乘一个小的可学习缩放（初值约 $10^{-4}$~$10^{-6}$），让初始状态下每层几乎”不发言”，深层网络因此不会一上来就把信号炸掉。这一招在 DeiT / CaiT 里被证明极有效，MoCo v3 也用。

7.5 药方四：优化器与超参（论文默认，实测要照抄）

项 取值 说明
优化器 AdamW（$\beta_2=0.95$） 不用 SGD。$\beta_2$ 调低是 ViT 训练的常见做法，防止二阶矩估计滞后

十、易混淆点与高频追问

Q1：v3 到底还算不算 MoCo？没有队列了，”动量”还在吗？
在。MoCo 的招牌是动量编码器（EMA 提供一致而稳定的 key），不是队列。队列只是”当年没有大 batch”的权宜之计。所以删掉队列不改变方法内核，v3 论文标题里用的也是 MoCo。

Q2：既然 v3 需要 4096 的大 batch，那它在单卡上还能用吗？
能，但等价性打折扣。单卡 batch 若只有 256，负样本就从 4096 掉到 256，效果会明显下降——负样本数量是对比学习的命门（P3 已讲）。这也是为什么 v3 的复现门槛比 v1/v2 高：它把”显存”换成了”效果”。

Q3：双向损失 = 把 loss 乘 2 吗？
不是。乘 2 只改梯度尺度；双向改的是参与计算的视图组合——方向 B 里 $x_2$ 走进了带梯度的 encoder，这会让主干在”$x_2$ 这种增强”上也收到锚点梯度，是质的区别。

Q4：为什么 MoCo v3 的精度表里，ViT-L 反而不如 ViT-B 稳？
论文补充：ViT 越大，自监督越容易崩，需要的稳定性干预越多（冻结时间更长、更强的 LayerScale）。论文中确实观察到这个规模不稳定性，这也是后续 DINO、MAE 继续改进训练配方的原因之一。

Q5：v3 里的 BN 真的完全没有了吗？
主干（ViT）里没有 BN，但投影头（3 层 MLP）里仍然有 BN。这是一个刻意的折中：主干的样本独立性要保住（否则对比任务作弊），而输出层的尺度需要稳定（否则 loss 数值不稳）。

十一、本节在整门课中的位置

三点衔接提示：

  1. 为什么 DINO 也继承了”动量编码器”？ 因为 EMA 提供的 key 不需要梯度、分布一致，是自监督里最便宜的”稳定目标”。MoCo v3 把这套配方的适用边界从 CNN 推到了 ViT，DINO 直接沿用并加上了 centering/sharpening。
  2. 为什么 MAE 放弃了对比学习？ 对比学习在 ViT 上要 300 epoch 才到 76.7（ViT-B），而 MAE 用掩码重建 1600 epoch 能到 83+，且训练更稳。MoCo v3 的价值因此更多是”证明了 ViT + 自监督可行”，而不是终点。
  3. 本章的三条线（对比 / 自蒸馏 / 重建）现在都齐了，它们共同的底座都是 P7 的 ViT——这也回答了 P7 结尾提出的问题：后面三个模型全是”ViT + 某一种自监督范式”。

十二、本讲一句话总结

MoCo v3 = MoCo v1 的骨架（双编码器 + 动量 EMA）＋ ViT 骨干 ＋ 删掉队列改成 4096 大 batch（负样本从”借来的历史”变成”同一步的新鲜样本”）＋ 对称双向 InfoNCE（$\mathcal{L}(q_1,k_2)+\mathcal{L}(q_2,k_1)$，每个 step 算两遍前向）——配套的”冻结 patch projection、梯度裁剪、LayerScale、AdamW(β2=0.95)、10 epoch warmup”才是它真正的贡献：它第一次说明了在无 BN 的 ViT 上做自监督，靠的不是更强的目标函数，而是一套数值稳定性的工程纪律。三代演进一句话记住：v2 补增强和投影头，v3 换骨干、去队列、改双向，本质骨架从未改变。
