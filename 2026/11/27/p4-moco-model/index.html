一、视频信息与定位

本节定位 承接 P3 SimCLR，解决它最致命的工程痛点——负样本被 batch size 绑架。本节只讲原理与结构（不含代码），下一讲 P5 是同一模型的完整代码实现。

本节讲授脉络（讲师口述，时间点为该分P 内相对时间）：

  1. 00:00 MoCo 是什么：Momentum Contrast，一种”基于动量”的对比学习方法；
  2. 00:23 结构与 SimCLR 高度相似：两个 encoder，但把负样本也画出来了，分别叫 query 与 key；
  3. 01:28 为什么叫 query/key：本质是一个检索问题，key 存放在 Memory Bank（队列） 里；

  5. 03:57 Momentum Encoder：不参与梯度回传，用动量公式更新，m 近似于 1；
  6. 05:32 总结：MoCo 的两个改动——负样本装进队列、使用动量编码器；以及作者对”为什么要动量”的猜测。

说明：本分P 的 AI 字幕完整可用（185 条，420s ≈ 421s），以下大量引述讲师原话；字幕中”CCL2 / sin cl2 / 信息NCC”等均为 ASR 对 SimCLR / InfoNCE 的误识，已按上下文校正。

二、先把问题摆出来：SimCLR 的负样本困境

回顾 P3：InfoNCE 的分母是 $\sum_j \exp(\mathrm{sim}(z_i,z_j)/\tau)$，负样本越多，分母估计越充分，特征判别性越好。但 SimCLR 的负样本只能来自当前 batch：

  • 想扩负样本 → 必须扩 batch → 显存爆炸（4096 batch 需要 TPU 集群）；
  • 而且 batch 一过，这些负样本的特征就丢了，下一轮要重新算；
  • 更要命的是，负样本的”多样性”受限于一个 batch 内的图像分布。

MoCo 的思路可以用一句话概括：把负样本”存起来”重复用，用”一个跟着慢慢走的编码器”保证存下来的特征不过时。

三、结构详解：query、key 与 Memory Bank

3.1 与 SimCLR 的相同点与不同点

讲师的对照非常直白：MoCo 的结构”和我们之前的 SimCLR 是非常相似的，只是有一些地方会有一些区别”。

维度 SimCLR（P3） MoCo（本节）
编码器数量 两个 encoder，完全共享参数 两个 encoder：encoder（query 分支）与 momentum encoder（key 分支）
负样本来源 当前 batch 内的其他视图 队列（Memory Bank） 中历史 batch 的特征
负样本数量 $2N-2$，随 batch 走 队列长度 $K$（论文 65536），与 batch 解耦
编码器更新 两个都靠梯度 query 分支靠梯度；key 分支靠动量
损失 InfoNCE / NT-Xent InfoNCE（讲师原话：”没有什么特别的地方”）

3.2 query 与 key：这就是一次”以图搜图”

图 1：P4_25.png（00:25）。PPT 标题”基于对比学习 - MoCo 框架结构”。图中上方是 encoder（输入 $x^{query}$ 得到 $q$），下方是 momentum encoder（输入 $x^{key}$ 得到 $k_0,k_1,k_2,\dots$），两者之间标注动量更新 $\theta_k = m\theta_k + (1-m)\theta_q$，右侧是 queue（队列）与 contrastive loss、similarity。

讲师的原话把这件事讲得很透：

“这些 key 呢就好像说我们有一个数据库，或者说有一个缓存，或者说是一个队列，官方把它定义这个名字叫做 memory bank（内存银行）。”

所以整个流程可以按”以图搜图“来理解：

  1. 拿一张图 $x^{query}$，过 encoder 得到查询向量 $q$；
  2. 数据库（队列）里存着一堆历史 key 特征 $k_0,k_1,k_2,\dots$；
  3. 用相似度在库里检索，与 $q$ 最像的那一个就是正样本（图上标 + 的 $x_1^{key}$）；
  4. 其余全是负样本（图上标 − 的 $x_0^{key}$、$x_2^{key}$）。

图 2：P4_75.png（01:15）。PPT 标题”基于对比学习 - MoCo 正负样本标注”。图中把 $x_0^{key}$ 标为 −（负）、$x_1^{key}$ 标为 +（正）、$x_2^{key}$ 标为 −，队列里按 $k_0,k_1,k_2$ 排列，右侧对比损失只在 $q$ 与这些 $k$ 之间计算。

3.3 Memory Bank / 队列机制的文字推演

（1）为什么叫”bank”：它是一块先进先出（FIFO）的环形缓冲区，容量固定为 $K$。里面存的不是图片，而是图片经过 momentum encoder 后的特征向量（维度通常是 128 或 256）。

（2）一次训练迭代的完整推演：

设当前 batch 有 $B$ 张图，队列容量 $K=65536$，当前队列里有 $K$ 个 key 特征。

  1. 取正样本对：取 batch 中的图 $x$，做两次随机增强得 $x^{q}$ 与 $x^{k}$；
  2. 算 query 特征：$q=f_q(x^{q};\theta_q)$，这是当前时刻、当前参数算出来的，梯度会回传；
  3. 算 key 特征：$k_+=f_k(x^{k};\theta_k)$，用 momentum encoder 算，不建梯度（torch.no_grad()）；
  4. 组 logits：$q$ 与队列里全部 $K$ 个 key（其中包含刚算出的 $k_+$）做内积，得到 $1 \times (1+K)$ 的 logits；正样本在第 0 位，其余 $K$ 个都是负样本；
  5. 算 InfoNCE：
$$ \mathcal{L}_q=-\log\frac{\exp(q\cdot k_+/\tau)}{\exp(q\cdot k_+/\tau)+\sum_{i=1}^{K}\exp(q\cdot k_i/\tau)} $$
6. **反向传播**：梯度只更新 `encoder` 的参数 $\theta_q$； 7. **动量更新**：$\theta_k \leftarrow m\theta_k+(1-m)\theta_q$，$m=0.999$； 8. **入队/出队**：把本 batch 的 $B$ 个 $k$ 特征压入队尾，同时弹出队头最老的 $B$ 个，保持队列长度恒为 $K$。

（3）这个设计为什么能”省算力还变强”——讲师原话：

“队列的设计它可以减少计算量，因为我每次都不需要去计算它这个特征了，我每次只是通过检索的方式直接获得；而且它可以扩大每一个 batch size 里面所装载的负样本数量。”

  • 省算力：历史特征复用，不用每步重算 $K$ 个负样本的前向；
  • 增强度：$K=65536$ 远远超过任何 batch，负样本覆盖了大量历史样本，分布更多样；
  • 解耦：负样本数量不再是 batch size 的函数，小显存也能玩大对比。

（4）代价：特征”不同步”。队列里的 key 是过去很多步、用旧参数算出来的，与当前 $q$ 不在同一个特征空间里。这就是 MoCo 必须配一个”慢慢走”的 encoder 的原因——见下一节。这也是 AI 大纲里”Memory bank 优缺点”那两页要讨论的核心。

图 3：P4_185.png（03:05）。PPT 标题”基于对比学习 - MoCo 图示 Memory bank 标注”，把 Memory bank 明确画在 queue 位置上，$k_0,k_1,k_2$ 为其中存储的 key 特征，momentum encoder 负责产生这些特征。

图 4：P4_240.png（04:00）。PPT 标题”基于对比学习 - MoCo 模型参数标注”，明确标出 encoder 参数为 $\theta_c$、momentum encoder 参数为 $\theta_k$，中间是 Memory bank/queue，右侧 contrastive loss 与 similarity 的连接关系。

四、核心创新：动量更新（Momentum Update）

4.1 公式

$$ \theta_k \leftarrow m\,\theta_k + (1-m)\,\theta_q,\qquad m\in[0,1),\ \text{典型值 }0.999 $$
  • $\theta_k$：momentum encoder（key 分支）参数；
  • $\theta_q$：encoder（query 分支）参数，由对比损失的梯度正常更新；
  • $m$：动量系数，一个”近似于 1”的超参数。

4.2 直观解释：指数滑动平均（EMA）

把公式展开成递推形式（令 $\theta_k^{(t)}$ 为第 $t$ 步的值）：

$$ \theta_k^{(t)} = m\,\theta_k^{(t-1)}+(1-m)\,\theta_q^{(t)} = (1-m)\sum_{i=0}^{t-1} m^{\,i}\,\theta_q^{(t-i)} + m^{\,t}\theta_k^{(0)} $$

也就是说，$\theta_k$ 是历史所有 $\theta_q$ 的加权平均，权重按 $m^i$ 指数衰减：越近的参数权重越大，越老的越小但不会归零。$m=0.999$ 时，等效平均窗口约 $1/(1-m)=1000$ 步。

讲师的原话把这个”保守”说得很生动：

“momentum encoder 在参数更新的时候，它会更加多地考虑自己上一次的参数，然后在自己上一次的参数基础上，额外去加上一点 encoder 上面梯度反传得到的一些信息……相对来说会比较保守，每次只获得更新后的 encoder 的一小部分信息，而更多保持它原先的信息，做一个比较平滑的加权。”

打个比方：$\theta_q$ 是”急性子的学生”，每一步都大幅修正自己；$\theta_k$ 是”慢性子的老师”，只吸收学生每次修正的一小部分，走得很慢。这样队列里前后相隔上千步的特征，仍然处在同一个”坐标系”里，可以放心地和 $q$ 做内积。

4.3 为什么必须”慢”：作者的解释与讲师的诚实

讲师在这里有一段非常重要的”祛魅”：

“为什么我们要使用 momentum encoder 呢？这点其实它并没有理论的证明，主要是作者发现实验效果好……作者是猜测：如果不存在 momentum encoder，那么负样本在特征空间当中的分布会非常离散，网络就很难把它学习好；而使用了 momentum encoder 的更新方式，可以让特征空间当中这些负样本的分布更为集中，使得网络学习更好。这只是作者的一个猜测……像我们 AI 这个领域，肯定是实验效果越好，大家就认了。”

这段话值得记住两层：

  1. 机制层面（有共识）：队列里的 key 来自不同时刻的编码器，若 key 分支跟着 $q$ 分支剧烈变化，队列内特征会”新旧混杂、尺度不一”，对比学习就没有稳定参照系；EMA 让 key 分支平滑演化，保证跨 batch 特征的一致性（consistency）。
  2. 效果层面（经验性）：为什么”更集中就更好”缺少严格证明，属于实验结论。做研究时不必把这句话当定理背。

图 5：P4_335.png（05:35）。PPT 标题”基于对比学习 - MoCo 标注 inference 与 m-encoder”，画面正中给出动量更新式 $\theta_k=m\theta_k+(1-m)\theta_q$，右侧标注 momentum，把 encoder θ_c 与 momentum encoder θ_k 之间的单向信息流画清楚（只有 $\theta_q \to \theta_k$，反向不存在）。

图 6：P4_375.png（06:15）。PPT 同一页的讲解状态，用于说明参数更新的细节与训练稳定性：key 分支不接收梯度，只做动量拷贝，因此队列中的特征演化平滑。

六、MoCo 与 SimCLR 的取舍：一张对照表

维度 SimCLR MoCo v1
负样本池 batch 内（≤ 8192 视图） 队列（65536 个 key）
显存压力 极大（batch 直接决定负样本数） 小（负样本存在队列里，不占计算图）
负样本一致性 完美（同一时刻同一编码器） 有”新旧混用”，靠 EMA 缓解
编码器 两个共享参数 query 分支 + 动量分支（不共享梯度）
训练稳定性 对 batch/温度敏感 相对更稳（EMA 起到平滑作用）
额外超参 $\tau$、batch $\tau$、$m$、队列长度 $K$

一句话总结取舍：SimCLR 用”钱（显存）”换负样本一致性，MoCo 用”一个慢编码器 + 一个队列”换取负样本规模。

七、易错点与面试追问

易错点 1：momentum encoder 不是”参数冻结”。 它一直在更新，只是更新方式换成 EMA；冻结（freeze）是 $\theta_k$ 完全不动，两者完全不同。

易错点 2：动量系数写反。 正确是 $\theta_k\leftarrow m\theta_k+(1-m)\theta_q$，$m$ 乘在旧参数上；写成 $m\theta_q+(1-m)\theta_k$ 就等于”keys 追着 query 跑”，队列立刻失效。$m$ 接近 1 表示”key 更保守”。

易错点 3：梯度不能流到 key 分支。 必须 torch.no_grad() 包裹 key 前向，否则会既浪费显存，又破坏”队列特征来自慢编码器”的前提。

易错点 4：队列里存的是”特征”，不是”图像”。 存图会导致每步要重算 $K$ 次前向，MoCo 省算力的设计就没了。

易错点 5：正样本也来自队列这一说法不准确。 正样本 $k_+$ 是本步新算的（来自同一张图的另一增强），旧队列里与它同源的历史特征其实也是”正样本”，但 MoCo v1 只把最新的那个当正、其余当负——这是后来 MoCo v3、DINO 想改进的地方。同理，队列中会有”同类不同图”的样本被当负样本（false negative）。

易错点 6：MoCo 的损失不是新东西。 讲师原话：”MoCo 使用的就是我们先前介绍的这个 InfoNCE 的 loss，没有什么特别的地方。”创新全在结构（队列）与更新方式（动量）上，不在损失函数。

面试追问 1：MoCo 解决了什么？用一句话说。
答：把对比学习的负样本数量从 batch size 中解绑——用固定容量的 FIFO 队列存放历史 key 特征，再用动量编码器保证这些历史特征与当前 query 处于可比的特征空间。

面试追问 2：为什么队列需要动量编码器，而 SimCLR 不需要？
答：SimCLR 的负样本与锚点由同一套参数、同一时刻算出，天然一致；MoCo 的负样本跨了上千步，若 key 编码器快速漂移，队列里就是”不同尺度的特征混在一起”，内积失去意义。EMA 让 key 分支平滑演进，把这种漂移压到可接受范围。

面试追问 3：$m$ 取 0.9 和 0.9999 分别会怎样？
答：$m$ 太小 → key 分支紧跟 query，队列特征迅速”过期”，一致性差；$m$ 太大 → key 分支几乎不动，虽然一致性好，但学不到新信息、特征滞后严重。论文用 0.999（约 1000 步窗口）取得平衡。

面试追问 4：MoCo 后来怎么演进的？
答：v2（P8 之前的内容）加了 MLP 投影头、更强的数据增强；v3 直接把 backbone 换成 ViT，移除了队列改用大 batch，并引入双向/对称对比损失、冻结 patch embedding 等稳定训练技巧（对应 P8 3.2）。也就是说，”队列”这个 v1 的核心设计在 v3 中被放弃了，但”动量编码器”被保留下来。

八、本节小结

  1. MoCo = Momentum Contrast，CVPR 2020，何凯明一作；把对比学习从”依赖超大 batch”改造成”依赖队列”。
  2. 结构上仍是”两个编码器 + InfoNCE”，但把 query 与 key 的关系明确成一次检索：query 去 memory bank 里找最像的 key，最像的那个是正样本，其余是负样本。
  3. 与传统检索的唯一区别：标签不是人给的，而是同一张图的两次数据增强”造”出来的伪标签。
  4. 两个核心改动：
    • 队列（memory bank）：FIFO、容量 65536、存特征不存图；省算力、扩负样本、与 batch 解耦；
    • 动量编码器：$\theta_k\leftarrow m\theta_k+(1-m)\theta_q$（$m=0.999$），key 分支不接收梯度，以 EMA 方式平滑跟随，保证队列内特征一致性。
  5. 关于”为什么要动量”，作者也只给了猜测（让负样本特征分布更集中），缺少理论证明——实验效果好是它被接受的真正原因。
  6. 记住一句话：SimCLR 用显存换一致性，MoCo 用动量换规模。 下一讲 P5 将把本节结构落成可运行的 PyTorch 代码（ResNet50 backbone、4096 队列、$m=0.99$、64×4097 的 logits 与交叉熵）。
