二、先把整份代码的骨架看清楚

在逐行拆解之前，先看全貌。整套实现只有 约 130 行，可以分成两块：“一次性准备” 与 “每个 batch 反复做”。

一句话记住 MoCo 的代码本质：它就是在 SimCLR 的”两次增强 + InfoNCE”骨架上，加了两件东西——一个不参与反传、靠动量跟随的 key 编码器，和一个存放历史 key 的环形队列。

3.2 数据加载：CIFAR-10 + DataLoader(batch=64)

讲师的说法是”我们加载 CIFAR-10 这样一个非常通用的一个数据集来做一个演示，无非就是说我们初始化一个 Dataset，然后呢我们加在这里一个 DataLoader，我们的 batch size 呢取 64”。

图 2：P5_80.png（01:20）。代码页，上半部分是 resnet50(output_dim) 的定义（取 resnet50、替换最后一层全连接），下半部分是 CIFAR10 数据集与 DataLoader 的构建。

三个工程细节值得强调：

  1. drop_last=True：MoCo 的队列入队是”一次塞进 64 列”，若最后一个 batch 只有 37 张，切片长度就会和 k 的行数对不上。丢掉它是最省事的做法。
  2. 这里不做 transforms.RandomResizedCrop：因为讲师把数据增强单独抽成一个函数（3.8 节），用”加噪声”替代了 SimCLR 的强增强。数据集这里只负责 ToTensor。
  3. 标签 y 全程不用：这就是”自监督”的字面含义——for x, y in loader 里 y 只占位，_ 掉即可。真正的”标签”是数据增强造出来的伪标签（正样本对）。

3.3 backbone：ResNet50 + 自定义输出维度

讲师原话：”在 backbone 网络这边呢，我们使用 ResNet50 作为我们的 backbone，我们首先需要去定义一个 resnet50 的网络结构，我们的 output_dim 呢就代表是说我们希望这个 resnet50 它的输出的这个维度是多少，那我们直接调用 ResNet50，然后呢我们可以把它的最后一层变成我们希望的它的一个维度。”

维度说明：ResNet50 在 layer4 之后、avgpool 之后得到的是 (N, 2048) 的全局特征，原来的 fc 是 2048 → 1000（ImageNet 类别数）。这里把 fc 换成 2048 → 1024，于是整个网络的输出就是 (64, 1024)——正好是队列里每一列（一个负样本）的维度 C = 1024。

为什么是 1024 而不是 128？ MoCo 论文里投影头是 128 维，MoCo v2 是 256 维。本讲为了和后面的 C 统一、便于口算，取了 1024。维度本身不参与算法逻辑，只要”编码器输出维度 = 队列的行数 C”这一条对上就行。这也是初学者最容易踩的坑：把 output_dim 和 C 写成两个不一致的数，后面 torch.matmul(q, queue) 会直接报 shape mismatch。

关于 CIFAR-10 的 32×32 输入：ResNet50 原生是为 224×224 设计的。32×32 走 conv1(k=7,s=2) 变 16×16，maxpool 变 8×8，到 layer4 结束是 1×1，avgpool 后仍是 1×1，能跑通，只是感受野利用率低、绝对精度不高。作为”理解 MoCo 流程”的教学实现完全够用；真要复现论文效果，请换 ImageNet 尺寸或 CIFAR-10 专用的 resnet_cifar（把 conv1 换成 3×3/s=1、去掉 maxpool）。

3.4 超参数：C、K、N、m、T

图 3：P5_150.png（02:30）。代码页，包含数据集加载、两个编码器的初始化，以及 C、K（队列长度 4096）、N（batch size）等超参数的定义。

讲师的解释非常口语化但抓住了要点：

“这个 C 指的是我们所需要的这个队列，也就是说这个内存银行，它的每一个的这个维度的大小；而 K 呢指的是说我的这个内存银行当中、这个队列当中最多可以存储多少个负样本，那这里呢我们取得比较大，我们取 4096 个，这样的一个非常大的一个负样本的一个容量；而 N 呢指的是这里的 batch size。”

符号 含义 取值 出现在哪个张量里
C 特征维度 1024 q/k: (N, C)；queue: (C, Kb)
Kb 负样本容量 4096 queue: (C, Kb)；l_neg: (N, Kb)
N batch size 64 q/k/l_pos: 第 0 维 = 64
m 动量 0.99 动量更新公式
T 温度 0.07 logits / T

m = 0.99 意味着什么？ 讲师说”他每次都以 0.99 这个非常大的这个权重来加权自己原先的这个参数，然后只有剩下的 0.01 的这个权重来参考 encoder 这边的一个参数”。换成一个更直观的说法：Fk 每步只向 Fq 挪动 1%，其参数更新的”半衰期”约为 步，也就是要走过近 70 个 batch，Fk 才有一半的权重来自新参数。这正好保证了队列里存储的、由 Fk 产出的历史特征前后一致、不过时。

3.5 双编码器 Fq / Fk 的初始化

讲师原话：”我们需要去初始化两个 encoder 的模型，那么刚开始呢我们给它都初始化成 resnet50 的模型就可以，比如说我们把其中一个模型叫做 Fq，另外一个模型呢叫做 Fk。而最开始的时候呢，这两个模型其实是一样的，所以说在最开始的时候呢，我们把 Fq 的参数直接给复制过来，给到 Fk。”

两个必须理解的点：

  1. 为什么初始必须相同？ 若 Fq 和 Fk 随机初始化成两套不同参数，那么同一个 batch 的 q 和 k 天然就不在同一特征空间，”正样本相似度高”这一学习目标从一开始就自相矛盾。所以 MoCo 的做法是：起点一致，之后靠动量缓慢分叉。
  2. load_state_dict 而不是 Fk = Fq：若写成 Fk = Fq，两者其实是同一个 nn.Module 对象，参数共享，Fk 的参数会被优化器一起更新，动量就彻底失效了。必须深拷贝（load_state_dict 或 copy.deepcopy）。

3.6 队列初始化与指针

讲师原话：”我们来初始化我们的这个队列，我们给它初始化成 C 乘 K 的这样的一个维度，然后呢把它放到 GPU 上面去。而对于每个队列呢，我还需要有一个指针来代表我这个队列目前已经操作到了哪一步。”

维度必须记牢：

  • queue.shape == (1024, 4096)
  • 沿 dim=0（行） 是”一个负样本的 1024 维特征”，所以归一化是 dim=0；
  • 沿 dim=1（列） 是”第 j 个负样本”。

易错点：很多人把 queue 建成 (Kb, C)，然后在 torch.matmul(q, queue) 时才发现形状对不上。记住一个口诀——“队列和 q 相乘，q 是 (N, C)，那 queue 必须是 (C, Kb)”，这样 (64,1024) @ (1024,4096) = (64,4096)，正好是”64 张图 × 4096 个负样本”的相似度矩阵。

queue_ptr 是干嘛的？ 它就是一个”写指针”，指向队列里下一列可以覆盖的位置。因为队列是 FIFO 的环形缓冲区，写满 4096 列之后从头覆盖，因此指针需要取模（见 3.10 节末尾）。

3.7 优化器：Adam，只优化 Fq

讲师原话：”我们需要去定义一个优化器，比如说我们使用 Adam 的这样一个优化器，它的 learning rate 我们取 0.001，而这个优化器呢，它只对 Fq 进行梯度的反向传播，因为我们在 MoCo 的实践当中呢，我们只有 encoder 它会进行梯度反传，而 momentum encoder 它的参数呢是根据我们这个 m 的一个加权重量更新来进行的。”

图 4：P5_300.png（05:00）。代码页，含优化器设置、数据增强函数，以及 InfoNCE loss 函数的结构（loss 名与 temperature 参数可见）。

这一行是整份代码里”信息量最密”的一行。Fq.parameters() 而不是 list(Fq.parameters()) + list(Fk.parameters())，这个选择直接决定了动量机制的存在意义：

如果传了 会发生什么
只传 Fq.parameters()（本讲） Fk 完全没有梯度来源，只能靠 3.10 的动量公式被”拖动”，MoCo 机制成立 ✅
传了两个 Fk 收到梯度并被 Adam 更新，等价于两个普通编码器，动量与队列都失去意义 ❌

3.8 数据增强：加 0.1 的随机噪声

讲师原话：”我们还需要去定义一个数据增强的一个方法，这里呢为了简便的一个期间呢，我就使用一个非常简单的一个数据增强的一个方式，我们直接在原先的这个图像上呢，加上一点随机的 0.1 的 10% 的加一个劳动（噪声）。在真实使用当中呢，我们会使用 torchvision 他们中的这个数据增强的手段来对原始的这个图像进行一个增强。”

这个”玩具级增强”只是为了让代码能跑、能看懂流程。增强越强，正样本对越难对齐，特征越有用——这正是 SimCLR 论文的核心经验（随机裁剪 + 颜色抖动的组合最有效）。工程上应替换为：

3.9 训练循环前向：两路增强 → 双编码器 → detach

讲师原话：”现在呢我们就需要正式的进入网络的一个训练的过程。那么我们每次呢都从这个 DataLoader 当中去取到一批的数据，而对于每一个每一张图像呢，我们都需要给它放到这个 GPU 上面去，然后呢对于每张图像我们会进行两个增强，一个变成 Xq，一个变成 Xk。然后对于 Xq 的这个图像呢，我们要给它送入叫 Fq 的这个 encoder 当中去，而对于 Xk 的这个图像呢，我们要给他送到 momentum encoder 当中去，这个 momentum encoder 呢它是 Fk。”

然后是整份代码里最容易被忽略、但绝对不能删的一行：

“我们还需要去做一步，k = k.detach()。这个什么意思呢？就是我现在呢要把 momentum encoder 这个分支的这个参数呢给它冻一下住，我们在这个步骤当中呢，我们不让它这个 momentum encoder 他参与梯度的一个回传，那这个也是 MoCo 它自有的一个设计。”

k.detach() 到底做了什么？它不是”把 Fk 的参数冻结”，而是”把 k 这个张量从计算图上摘下来”。具体差异：

写法 梯度会流回 Fk 吗 效果
k = Fk(xk) 会（若无 requires_grad=False） backward() 时 Fk 收到梯度，MoCo 退化
k = k.detach() 不会（计算图在 k 处被剪断） 只有 Fq 更新；Fk 只能靠动量公式 → MoCo ✅
p.requires_grad=False for Fk 也不会 同样有效，但不省前向显存的关键在于 detach

两者都做（本讲代码即如此）是最稳的写法。还要注意一点：k 不能加 torch.no_grad() 包住整个 Fk(xk) 后再拿去算 loss 吗？ 可以，等价写法：

3.10 InfoNCE loss 函数：三个参数 + 温度

讲师原话：”我们现在拿到了一个 Q，拿到了一个 K，我们就可以将 Q 和 K 呢放在一块去计算这个 InfoNCE 的 loss，它需要三个参数，分别是 Q 和 K 的值，以及我们的这样的一个设置的内存银行（队列）。那除了 Q、K 和队列这三个参数之外呢，我们还需要定义一个 temperature，比如说我们就定义成 0.07。”

下面把 ④~⑥ 的”为什么”逐条讲透，这也是讲师花了最多时间解释的部分。

（1）为什么矩阵乘法就等于余弦相似度

讲师原话：”为什么说我们使用矩阵乘法就可以得到相似度呢？那么在求这两个向量的 cosine 的时候，它是有两个向量的内积，然后除上两个向量的这个模的一个长度，那么其实呢这个模的这个长度、分母的这个模的这个长度呢，它其实是一个常量，我们不需要关注，所以说我们只需要对两个向量进行一个内积的一个操作，也就是一个矩阵的一个乘法，其实我们就可以间接的表示这两个向量的一个相似度。”

数学上：

而第 ① 步的 F.normalize(p=2, dim=1) 已经让 ，于是

所以归一化之后，内积与余弦相似度完全等价，相似度范围被压到 。这一步是必须的：若不做归一化，ResNet 输出的模长差异会主导相似度——某个模长特别大的样本会和所有 q 都很”像”，softmax 直接被它支配。

（2）bmm 与 matmul 的分工

讲师原话：”我们用 bmm 的这个函数，所谓的 bmm 它指的是 batch 上面的一个矩阵乘法。那么对于 Q 和 K 呢，它本来其实是 64×1024 的，我们现在呢把 Q 给它变成 64×1×1024，然后把 K 呢给它变成 64×1024×1……那么我们调用这个 bmm 算法呢，它就是在保持 batch 的情况下，对后面这两项进行一个矩阵乘法的一个操作。”

调用 作用范围 用在本讲哪里
torch.bmm(A, B) 批量矩阵乘（要求 3D：(B,n,m) @ (B,m,p)） 正样本：64 个独立的”1×1024 与 1024×1”
torch.matmul(A, B) 通用乘法，2D 时退化为普通矩阵乘 负样本：(64,1024) @ (1024,4096)

l_pos 为什么必须是”批量的 1×1”而不是”整体的 64×64”？因为我们要的是逐样本配对：第 i 行的 q_i 只和第 i 行的 k_i 算相似度，得到 64 个标量。如果用 q @ k.T 得到的是 (64, 64) 的全对全相似度矩阵，那第 i 行里还混着”q_i 与其他样本的 k_j“——虽然在 InfoNCE 的语义下它们确实是负样本，但会与队列里的负样本重复计数，本讲的简化实现刻意避开了这个复杂度。

（3）squeeze 与 cat：为什么是 64×4097

讲师原话：”由于我们 positive similarity 它是 64×1×1，所以后面两个维度我们并不需要，所以说我们给它做一个 squeeze 的操作，把后面的两项给他压掉。这样的话相当于我们会得到一个 64 乘 4097 的、一个东西。”

  • l_pos: (64, 1, 1) → squeeze(-1) → (64, 1)
  • l_neg: (64, 4096)
  • torch.cat([l_pos, l_neg], dim=1) → (64, 4097)

于是每一行 = 1 个正样本相似度 + 4096 个负样本相似度。讲师的原话：”一共有 64 行，第 0 位呢代表的就是它正样本的相似度，而后面的这个 4096 个呢，代表的就是它的负样本的一个相似度。”

易错点：cat 的 dim 必须是 1（列方向拼接）。写成 dim=0 会得到 (4160, 1)，后面 cross_entropy 直接报错。

（4）标签为什么全 0

讲师原话：”我们还需要去创建一个全零的一个 label，这个全零的 label 呢其实就是一个 64，然后全部都是零的一个东西……其中第一位呢代表的是 64 张图像当中正样本它的一个相似度……我们可以把它看成就是一个分类的一个任务，这里的每一列呢代表的就是我分成每一个类的一个概率，那么我们肯定最后希望的是说，我们分类成它正样本的这个概率最大，也就是我们希望第一列的这一个得到的概率是最大的，也就是说我们希望说它尽可能的分成零这一类。”

把 InfoNCE 重新表述成一个 4097 分类问题：

  • 输入：一行 4097 维的 logits；
  • 类别：第 0 类是”正样本”，第 1~4096 类是”4096 个负样本”；
  • 正确答案：永远是第 0 类（因为这一行里排第一的就是它自己的正样本）；
  • 所以 labels = zeros(64)，每个样本的目标类别索引都是 0。

（5）温度 τ = 0.07 的作用

讲师原话：”这个 temperature 呢指的是说，我在计算 cross entropy 的时候，我们对于这个 logits 和这个 label，它都需要除上这样的一个数，也就是说这个公式当中的这个 τ。”

越小，softmax 越”尖锐”：相似度上的微小差距被放大成概率上的巨大差距，模型被迫去区分”很像的负样本”（hard negative），特征更细粒度； 过小则训练不稳定、梯度爆炸。0.07 是 MoCo / SimCLR 的经验值（论文用 0.07 或 0.2）。

3.11 反传与手写动量更新

讲师原话：”我们再把 InfoNCE loss 给计算好之后呢，我们就可以做这个梯度的反传。但是呢我们还是需要去注意到我们的 encoder 他是参与梯度反传的，我们 momentum encoder 他其实并没有参与这个梯度的反传……所以说我们需要手动的对 momentum encoder 它这个参数进行一个更新。那么我们可以把 momentum encoder 里面的这个参数全部都给它拿出来……我们让这个 Fk 的一个参数在它自己先前那个参数的基础上，去乘上我们所说的这个 m 这样的一个系数，然后呢再加上 Fq 它这个参数，然后乘上一个 1-0.99，0.01 这个东西。”

关于 param_k.data 与 param_q.detach()：

  • 必须加 .data 或用 torch.no_grad()：否则这两步会被记进计算图，PyTorch 会认为”参数 k 是由参数 q 计算出来的”，于是 loss.backward() 时梯度会顺着这条路径反向传播到 Fq，同时也会在 optimizer.step() 之外再次修改参数（更严重的是可能报 “a leaf Variable that requires grad is being used in an in-place operation”）。
  • 等价写法：param_k.copy_(m * param_k + (1 - m) * param_q) 或 param_k.lerp_(param_q, 1 - m)（lerp_ 是原地线性插值，最简洁）。

动量更新的物理意义（讲师原话）：”我每次更新 momentum encoder 的时候，我有 99% 的这个权重参考的是他上一次的这一个参数，而只有 0.01% 的这个权重呢参考的是 encoder 这边梯度反传过来的一个参数。”

3.12 队列入队与指针环形滚动

讲师原话：”除此之外呢，我们还需要去做一件事情，我们需要把这一批拿到的这个 Q 和 K 给他放进队列。因为我们这一次虽然说 Q 和 K 它是正样本，但是我们在下一个 batch 当中呢，我们会拿到新的一批数据进来，那这个时候我的 Q 和 K 它对于新的数据来讲就是负样本，就是说我们可以直接的把 K 给它加到这个队列当中去。我们每一次更新队列的时候呢，我会有一个 batch，然后呢我们将这个指针以上加上 batch size，我把这个 K 的值呢给它放进来，然后呢我对这个指针进行一个更新……那么当它这个移到 4096 之后呢，它就会循环的回到前面来。”

三个细节：

  1. 必须 .T 转置：k_norm 是 (64, 1024)（batch 在前），而 queue 是 (1024, 4096)（特征在前），切片 queue[:, ptr:ptr+64] 的形状是 (1024, 64)，所以要用 k_norm.T 把 (64,1024) 转成 (1024,64)。
  2. 入队的是 k 而不是 q：q 是”查询”，用完即弃；k 是被冻结的 Fk 产出的、稳定的”锚点特征”，只有它进队列才能保证队列里所有特征来自同一个缓慢演化的编码器，可比性才成立。这也解释了为什么需要动量编码器——若用 Fq 入队，队列里的旧特征和新特征来自”每步都在跳”的编码器，尺度不一致，相似度计算就失真了。
  3. 指针取模 % Kb：4096 / 64 = 64，整除，所以本讲里指针永远落在 0、64、128、…、4032，写满一次正好 64 个 batch 完成一轮覆盖。若换成 Kb=1000、bs=64，就一定会发生环形跨越，必须用上面的 else 分支。

六、易错点、坑与面试追问

6.1 五个高频坑

  1. 忘了 k.detach()，loss 还降、但方法是错的。这是最隐蔽的坑：不 detach 时模型也能训练、loss 也会下降（因为两个编码器都被优化了，任务变得更容易），但你已经不是在跑 MoCo 而是”共享队列的双塔 SimCLR”，负样本一致性优势全无。验证方法：训练几个 batch 后打印 Fk 与 Fq 某个参数的差值，若两者的差异为 0 或极大，说明动量更新没生效。
  2. Fk = Fq 写成引用而非拷贝。Python 对象赋值，Fq is Fk 为 True，此时 optimizer.step() 更新的是同一组参数，打印 id(Fq.fc.weight) == id(Fk.fc.weight) 会发现相同。必须 load_state_dict / deepcopy。
  3. 入队忘了 F.normalize。队列里混入未归一化的向量，l_neg 的数值尺度远大于 l_pos，softmax 后负样本概率接近 1，loss 长期居高不下。
  4. queue_ptr 不取模。4096/64 整除时侥幸不报错，一旦改小 Kb（比如为了省显存设成 1000），第 16 个 batch 就会 IndexError。
  5. optimizer.zero_grad() 放在 backward() 之后。梯度跨 batch 累积，动量编码器的手写更新会把累积的脏梯度动量带进去，训练发散。

6.2 面试追问与参考答法

Q1：为什么动量编码器不用优化器更新，而要手写动量？
A：三个原因。① 若 Fk 也用梯度更新，则队列里的历史 key 与当前 key 来自”每步都在跳”的编码器，特征尺度不一致，负样本对比失去意义；② 动量更新让 Fk 的演化极其平滑（m=0.99，半衰期约 69 步），保证队列内特征在时间上可比；③ 省掉一半的反传与优化器状态，显存与算力都省。

Q2：k.detach() 和 Fk.requires_grad_(False) 是一回事吗？
A：效果上都阻止梯度回传到 Fk，但机制不同。detach() 剪断的是张量与计算图的连接，k 之后的所有运算（loss）都不会把梯度传回去；requires_grad=False 关的是参数，Fk 的前向仍会构建计算图（因为输入 xk 若 requires_grad 则输出也 requires_grad），只是叶子结点不收梯度，显存开销仍在。要彻底省显存应使用 with torch.no_grad():。

Q3：队列越长越好吗？
A：不是简单的正相关。队列越长，负样本估计越充分，但队列中的特征也越”旧”——由更早版本的 Fk 产出，与当前 q 的特征空间存在偏移。MoCo 论文的消融显示 K 从 256 增到 65536 时性能持续提升但收益递减，且必须配套越大越小的动量 m（队列长 → 特征老 → 需要更平滑的 Fk）。工程上 4096~65536 是常见区间。

Q4：为什么入队的是 k 而不是 q？
A：q 来自 Fq，每步都在剧烈变化；k 来自被动量平滑的 Fk，是”稳定锚点”。队列的全部意义是”提供与当前 query 同一特征空间的历史负样本”，只有 k 满足这一点。且 q 参与反传，若入队还需额外 detach 与归一化，徒增风险。

Q5：温度 τ 调到 0.01 会怎样？
A：softmax 极度尖锐，梯度只由最难的负样本主导，容易数值溢出（exp 爆炸）且训练不稳定；τ 太大（如 1.0）则分布过平，模型学不到区分性，容易坍缩到所有样本相似度相近。0.07 是实践中的甜点。

Q6：MoCo 与 SimCLR 的本质差别用一句话说？
A：SimCLR 用”大 batch”造负样本，MoCo 用”队列 + 动量编码器”造负样本——前者买显存，后者买设计。

七、小结

本节把 P4 的结构图变成了可运行的 130 行代码，核心只有三个”反常识”的设计：

  1. k.detach() 让 key 分支不收梯度——不是为了省算力，而是为了让 Fk 只能沿动量轨迹缓慢演化，从而与队列中”历史特征”保持一致；
  2. 队列 (C, Kb) = (1024, 4096) 把负样本从 batch 里解放出来——负样本量从”受显存约束的 126”变成”固定的 4096”，且只花 16 MB 显存；
  3. CrossEntropyLoss(logits, zeros) 就是 InfoNCE——所谓对比学习损失，本质是一个”4097 类的分类任务，正确答案永远在第 0 类”。

与前后章节的关系：

  • 向前：P3 给了 InfoNCE 的公式，P4 给了队列 + 动量的结构图，本节把两者缝合成代码；
  • 向后：P8 的 MoCo v3 会砍掉队列（改用大 batch）、把 backbone 换成 ViT、引入对称双向损失（q、k 互换再算一次）。理解了本节的”队列 + 动量”，才能看懂 v3 到底改了什么、为什么改。

一句话记住本节：MoCo 的实现 = SimCLR 的骨架（两增强 + InfoNCE）+ 一个 detach 的 key 编码器 + 一个 (1024,4096) 的环形队列 + 8 行手写动量更新。
