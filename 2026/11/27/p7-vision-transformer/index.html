二、先解决一个前置疑问：CV 的天下原本是 CNN 的

要理解 ViT 为什么值得单开一节，得先回到 2020 年之前的常识：图像任务默认用 CNN。

CNN 有两条与图像天然契合的”归纳偏置（inductive bias）”：

归纳偏置 含义 在 CNN 里的体现
局部性（locality） 相邻像素才相关，远处像素关系弱 3×3 / 7×7 的小卷积核
平移等变性（translation equivariance） 物体左移一格，特征图也左移一格 权重共享 + 滑窗

这两条让 CNN 在数据有限时极其高效——它不需要从数据里学”相邻像素应该相关”这件事，因为架构里已经写死了。

而 Transformer 恰恰相反：它没有任何局部性假设。自注意力让序列里任意两个位置直接交互，位置信息只能靠额外的位置编码注入。在 NLP 里这是优势（词序关系复杂、长距离依赖多），放到图像上就是”把先验丢了”。

ViT 论文的赌注是：当数据量足够大时，归纳偏置反而是束缚。手工写死的局部性会限制模型去发现长距离、全局性的规律；而只要给它 JFT-300M 这个量级（3 亿张图）的预训练数据，让 Transformer 从零学出”哪里该看、哪里该连”，效果就能反超最好的 CNN。

代价是算力：自注意力的复杂度是 ， 是序列长度。图像如果按像素当 token，224×224 = 50176 个 token， ，完全不可行。所以 ViT 的第一个工程决策就是——不按像素切，按 patch 切。这就是下一节的全部起点。

五、三个关键组件，逐个拆开看

图 2：P7_130.png（02:10 附近）。PPT 在总图基础上把注意力集中在中间这一段，明确标出三件事的组合顺序：Embedded Images → Linear Projection，然后 + [CLS] (Class Token)，再 + Position Embeddings，之后才进 Transformer Encoder，最后 MLP Head → Class。右下角的 Encoder 展开图标出 Norm / Multi-Head Attention / MLP。

5.1 Patch Embedding：本质是一个 stride = kernel 的卷积

“切块 + 展平 + 线性投影”这三步，用一个 Conv2d(kernel_size=16, stride=16) 就能一次性完成，而且数学上完全等价：

  • 卷积核在 16×16 的窗口上滑动，窗口不重叠（stride=16），正好覆盖一个 patch；
  • 每个输出通道是输入窗口的加权和 —— 这就是那一次线性投影；
  • 输出特征图大小 ，通道数 = 。

所以工程实现里没人真的去 reshape 切 patch，全部写成一个卷积层。这是读 ViT 源码时的第一个”恍然大悟点”。

5.2 Position Embedding：Transformer 本身不知道”谁在谁旁边”

自注意力是置换不变的：把 197 个 token 打乱顺序，输出只是跟着打乱，注意力本身察觉不到。但图像显然有空间结构——“左上角的天空”和”右下角的草地”必须区分开。所以必须在输入处注入位置信息。

ViT 用的是可学习的一维位置编码（nn.Parameter(torch.zeros(1, 197, 768))），而不是 Transformer 原版的 sin-cos 编码，也不是二维编码。论文做过消融，几种方案差别不大，一维可学习最省事。

三个必须知道的工程细节：

  1. 为什么一维就够：patch 序列是按行优先（row-major）展开的，一维索引与二维坐标之间存在确定的对应关系，模型能从索引里把二维位置”解码”出来，不需要显式给 。
  2. 位置编码是可学习的参数，不是函数：它属于模型权重，会参与训练、会被存进 checkpoint。这也是为什么加载预训练权重时 pos_embed 常常是形状不匹配的重灾区。
  3. 换分辨率必须插值：微调时把 224 提到 384，patch 数从 196 变成 ，位置编码表只有 197 行，装不下。标准做法是对 pos_embed 做双线性插值（先 reshape 成 14×14 的二维网格 → 插值到 24×24 → 展平回 577 行）。这一步在几乎所有 ViT 微调代码里都能看到。

5.3 [CLS] Token：把”整张图的摘要”托付给一个位置

[CLS] 是借自 BERT 的做法：在 196 个 patch 前面插一个可学习的空 token，它不代表任何图像区域，唯一作用是通过自注意力”收集”全局信息，最后用它的输出做分类。

为什么不用更直觉的”对 196 个 patch 输出取平均”（Global Average Pooling）？

  • 从机制上看，[CLS] 是一个可学习的聚合器：它自己会学”该关注哪些 patch、按什么权重汇总”，比固定的平均池化更灵活；
  • 从论文消融看，两者效果接近，但 [CLS] 与 BERT 完全同构，迁移代码零成本，所以成了默认方案；
  • 从工程上看，[CLS] 还带来一个好处：分类只依赖一个位置，下游接线性探测（P21 会讲）时直接取 x[:, 0] 即可。

图 2 页面上的一个细节值得强调：画面写的是 “Class Token 提取用于分类，其余 Patch 特征被舍弃”。这一点在分类任务里成立，但在多模态任务里就不成立了——后面 P16 的 CLIP、P20 的 LLaVA，都不会只取 [CLS]，而是把 196 个 patch 的全部输出都喂给后续模块（因为要做区域级对齐、要保留空间结构）。所以”只用 CLS”是分类头的用法，不是 ViT 的用法。

5.4 Transformer Encoder 内部：Pre-LN 与两处残差

图 3：P7_235.png（03:55 附近）。PPT 把 Encoder 展开成一个循环模块，标注 Embeded Patches → Norm → Multi-Head Attention → Norm → MLP，两处 Add 残差支路（图 1 中写作 Add & Norm），外层 L x 表示重复 L 层。

一层 Block 的计算（Pre-LN 形式，也是 ViT 论文与所有现代实现采用的形式）：

四个要点：

  1. LN 放在子模块之前（Pre-LN）：原版 Transformer 是 Post-LN（LN(x + Sublayer(x))），深层时梯度不稳、必须靠学习率 warmup 硬压。Pre-LN 让残差主路保持”干净”的恒等通路，梯度可以直接回传，深层也能训——这正是 ViT 能堆到 32 层（Huge）甚至更深的前提。
  2. LayerNorm 而不是 BatchNorm：LN 在单个样本内部沿特征维归一化，与 batch 大小无关；BN 依赖 batch 统计量，在序列任务上既不好用、又和”变长序列 + 大 batch 分布式训练”冲突。这一点在 P8 会变成一个关键话题：ViT 没有 BN，所以失去了 BN 带来的训练稳定性红利，自监督训练 ViT 极不稳定。
  3. GELU 而非 ReLU：与 BERT 一致，MLP 里用 GELU。
  4. MLP 是逐 token 独立作用的：token_mixing（注意力，跨位置）和 channel_mixing（MLP，跨特征维）交替进行，这是 Transformer 的经典分工，ViT 完全继承。

按大纲时间点 05:07 的表述，讲师的观点是：实验常用 ViT-Base，因为它能塞进单卡/少卡显存，不必盲目追求大模型。这是很务实的建议，展开成三条工程判断：

场景 推荐 理由
单卡（如 24G）做实验、跑通流程 ViT-B/16 86M 参数、17.6 GFLOPs，batch 32 可在单卡跑；预训练权重最丰富（ImageNet-21k、CLIP、DINO、MAE 都有 B/16 版本）

顺便解释”为什么大家嘴里的 ViT 常常不是原版 ViT”：这一点会在 P8 立刻派上用场——MoCo v3 里的骨干、CLIP 里的图像塔、MAE 里的 encoder，都是”ViT 结构 + 某种预训练方式”的产物，社区里统称 ViT，但权重分布和行为差别很大。选型时看 checkpoint 是怎么预训练的，比看结构是 B 还是 L 更重要。

七、”变种”到底指什么：四个方向的演化

标题写”ViT 与其变种”，但这一节只有 8 分钟，讲师把重心放在了架构与规模上，变种主要在后面的分P 展开。这里按”演化方向”做一张全景图，方便把后面几讲挂上去：

方向一：规模与分辨率变种（本节主体）

B / L / H / G 四档 × patch 8 / 14 / 16 / 32，以及 224 / 384 / 512 的分辨率组合。命名规则统一写成 ViT-{规模}/{patch}，如 ViT-B/16。

方向二：数据效率变种

原生 ViT 的软肋是”必须大数据预训练”。DeiT（Data-efficient Image Transformer）用蒸馏解决：引入一个 teacher（通常是 RegNet）和一个额外的 distillation token，让 ViT 在 ImageNet-1k 上从零训练也能到 80%+ top-1。这是”没有 3 亿张图也想用 ViT”的标准答案。

方向三：结构效率变种（砍 ）

模型 核心改动 解决的痛点
Swin Transformer 窗口内注意力 + 层级化下采样 + 移位窗口 把全局 变成窗口内线性，还能出多尺度特征图（接检测/分割）
PVT / CvT / Twins 金字塔结构 / 卷积嵌入 同上，面向下游密集预测
Hybrid（R50 + ViT） 先用 CNN 提特征图，再把特征图当 token 借用 CNN 的局部性，减少序列长度（论文表 2 里有 R50+ViT-B/16 一行）

方向四：预训练方式变种（第三章后半程的主线）

模型 预训练范式 对应分P
MoCo v3 ViT + 对比学习（动量编码器 + 双向损失） P8（下一讲）
DINO ViT + 自蒸馏（无负样本） P9 / P10
MAE ViT + 掩码重建（只编码可见 patch，省一半算力以上） P11 / P12
BEiT ViT + 掩码重建（token 分类） P6 已学

一句话总结变种逻辑：结构上的变种在解决”ViT 太贵”，预训练上的变种在解决”ViT 没标签怎么训”，规模上的变种在解决”要不要为了 1 个点精度多花 10 倍算力”。

三处最容易被写错的地方，单独提醒：

  1. batch_first=True 不能漏。nn.MultiheadAttention 默认输入是 (N, B, D)（序列在前），而 ViT 的习惯是 (B, N, D)。漏了这个参数不会报错，但会把 batch 维当序列维去做注意力——结果完全错，且很难发现。
  2. need_weights=False 建议带上。默认会返回 197×197 的注意力权重矩阵，多层多 batch 累积起来占显存可观，而我们通常不需要它。
  3. CLS 必须在最前面（x[:, 0]），位置编码的排布也要跟着一致。如果把 CLS 追加在末尾却仍取 x[:, 0]，就会取到第一个 patch 的特征，训练也能勉强收敛但精度明显偏低——这类 bug 的典型症状是”loss 能降、精度差 5~10 个点”。

十、本节在整门课中的位置与衔接

用一张图收尾，把 ViT 与前后各讲串起来：

三点衔接提示，学完本节就应该能自己回答：

  1. 为什么 MoCo v3、DINO、MAE 全都选 ViT 当骨干？ 因为 CNN 的局部性偏置在自监督里不是优势——自监督的核心是”从数据本身造监督信号”，模型越”白纸”，学到的东西越通用。ViT 恰好足够”白纸”。
  2. ViT 没有 BN，这对自监督意味着什么？ BN 在监督训练里有一个隐藏作用：它通过 batch 统计量提供了隐式正则与数值稳定。ViT 用 LN 就没有这个红利，于是自监督训 ViT 会崩——这正是 P8 那个”冻结 patch embedding”技巧要解决的问题。
  3. 为什么 CLIP/LLaVA 的视觉塔多用 ViT-L/14 而不是 B/16？ patch 14 换来了更细的粒度（224/14 = 16×16 = 256 个 token），对图文对齐更有利；而 L 规模提供了足够容量。这也是”规模变种 + patch 变种”在真实工程里的组合应用。
