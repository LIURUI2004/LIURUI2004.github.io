Adaptive-RAG 项目学习笔记（二）：LangGraph 与核心源码调用关系

本章整理此前已经学习过的 LangGraph 基础概念，以及 state.py、graph.py、chat_service.py 三个核心文件的分工。
阅读目标：能够顺着一次用户请求，讲清楚数据如何进入 Graph、经过节点处理，最后如何返回。

1. LangGraph 是什么？

LangGraph 可以理解为：把多个 Python 函数组织成一张可执行的工作流图，并管理它们之间的数据传递和执行顺序。

可以先把它想象成一张流程图：

  • Node（节点）：负责完成一项具体任务。
  • Edge（边）：规定节点之间如何连接。
  • State（状态）：保存工作流运行过程中的共享数据。
  • Graph（图）：组织节点、边和条件路由。

2. LangGraph 核心名词与 API

名词 / API 是什么 作用
State（状态） 工作流共享的数据 保存用户输入、中间结果和最终回答
AgentState 项目定义的状态类型 规定 State 可以有哪些字段
StateGraph LangGraph 的图构建器 创建一张以指定 State 为基础的工作流图
Node（节点） 通常是一个 Python 函数 读取 State、执行任务、返回状态更新
add_node() 节点注册方法 把函数注册为 Graph 节点
add_edge() 固定连接方法 指定一个节点完成后进入哪个节点
add_conditional_edges() 条件连接方法 根据条件函数的结果选择下一个节点
START 开始标记 表示工作流入口
END 结束标记 表示工作流结束
compile() 编译方法 将定义好的工作流编译成可执行对象
invoke() 同步执行方法 同步运行已编译的 Graph
ainvoke() 异步执行方法 异步运行已编译的 Graph
stream() / astream() 流式执行方法 逐步获取工作流执行过程或更新

关键理解：Node 通常从 State 读取数据，并返回一个字典，告诉 LangGraph 哪些字段需要更新。

例如：

  • state["user_query"]：读取用户问题。
  • return {"intent": ...}：提交需要更新的字段。
  • return {}：表示当前节点没有提交新的字段更新。

State 字段不是一开始就必须全部填满，而是随着工作流逐步产生。

5. 四个最重要的 Graph API

5.1 创建工作流：StateGraph()

含义：创建一张以 AgentState 作为状态结构的工作流图。

5.2 注册节点：add_node()

含义：把 planner_node 函数注册为名为 plan_tasks 的节点。

注意：注册节点不等于执行节点。 这一步只是告诉 Graph，工作流中存在这个节点。

5.3 建立固定连接：add_edge()

含义：plan_tasks 执行完成后，接着进入 execute_tools。

5.4 建立条件连接：add_conditional_edges()

三个部分：

  1. "route_complexity"：从哪个节点之后进行条件路由。
  2. route_function：负责判断并返回路由结果的函数。
  3. 字典：把路由结果映射到目标节点。

build_graph() 是构建工作流的函数。

这样更容易替换组件和进行测试。

8. state.py：AgentState 与初始状态

源码位置：app/agents/state.py，以及 chat_service.py 中的 _initial_state()。

8.1 AgentState 是什么？

AgentState 是项目定义的状态类型。

项目使用 TypedDict（用于描述字典字段及类型的类型标注工具）定义状态；total=False 表示字段不要求在每次初始化时全部提供。

8.2 此前学习到的初始 State 字段

字段 含义
trace_id 当前请求的追踪 ID
session_id 当前对话会话 ID
user_id 用户 ID
user_query 用户当前提出的问题
messages 近期对话历史
summary 历史对话摘要
retrieved_chunks 检索得到的文档片段
tool_results 工具执行结果
citations 回答使用的引用信息
refused 是否进入拒绝处理
step_count Agent 执行步骤计数
token_usage Token 使用统计
latency 各阶段耗时统计
confirm_action_id 用户确认操作相关的 ID
confirmed_action 已确认的操作信息
idempotency_key 幂等控制标识，用于避免同一操作被重复执行

注意：初始 State 不一定已经包含 intent、strategy、plan、final_answer 等字段。这些字段会在后续节点执行时逐步产生或更新。

9.3 compile() 和 ainvoke() 有什么区别？

compile()（编译方法）负责把已经定义好的工作流编译成可执行对象。它不代表已经处理了某个用户问题。

ainvoke()（异步执行方法）才是真正传入 State 并运行工作流。

result 通常是整个工作流执行后的最终 State，而不是单独的回答字符串。最终回答一般保存在：

之后 _to_response() 再提取回答和其他响应信息。

9.4 同步、异步和流式执行

方法 含义
invoke() 同步执行 Graph
ainvoke() 异步执行 Graph
stream() 同步流式获取执行过程
astream() 异步流式获取执行过程

项目使用 ainvoke()，是因为工作流中可能需要等待 LLM、数据库、检索器和工具等 I/O 操作。

注意：流式获取节点更新，不等于最终答案一定逐字流式生成；还需要看项目如何处理和发送这些事件。
