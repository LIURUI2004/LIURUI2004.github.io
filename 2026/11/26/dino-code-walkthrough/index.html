01 / 08 · 直觉先行｜DINO 在学什么，为什么不会坍缩

本节结论：DINO 是「无标签自蒸馏」——教师输出当软标签，学生去拟合，教师由学生的指数移动平均（EMA）得到；四个机制共同防止网络输出退化为常数。

1.1 一句话说清

把同一张图片做两次不同的「破坏」（裁剪、翻转、加噪），让网络对这两个视图给出尽可能一致的输出分布。全程不需要标签：训练循环里写的是 for x, _ in dataloader:，那个 _ 就是被丢弃的 label。

DINO 即 *self-DIstillation with NO labels*。它和 MoCo / SimCLR 那类对比学习最大的区别是：不需要负样本，也不需要显式对比损失，靠一个「慢慢移动的目标」自己给自己当老师。

1.2 最容易掉进去的坑：坍缩

如果没有任何约束，网络会找到一个稳赚不赔的解：不管输入什么，都输出同一个固定向量（所有维度概率都是 1/K）。两个视图当然「一致」，loss 立刻降到常数，但什么特征也没学到。这叫 collapse（表征坍缩）。

DINO 用四道防线联合堵死这条路：

机制 代码里怎么做 起什么作用
stop-gradient 教师分支 detach() / no_grad() 阻断「两边一起往常数跑」的退化路径，让教师成为缓慢移动的目标
EMA / momentum encoder θ_t ← λθ_t + (1−λ)θ_s 教师不是学生的即时镜像，而是学生的时间平均，目标更稳定
centering 教师 logits 减 c，c 用 batch 均值滑动更新 防止某一个输出维度长期霸占，把分布拉回均衡
sharpening 教师温度 τ_t=0.07 小于学生 τ_s=0.1 让教师目标更尖锐、更有信心，对抗 centering 带来的过度均匀

判断：centering 把分布摊平，sharpening 把分布捏尖，两者是一对反向力；EMA 让目标慢慢变，stop-gradient 保证梯度只更新学生。缺 centering 容易单维坍缩，缺 sharpening 容易均匀坍缩，四个机制必须成套使用。

02 / 08 · 数学形式｜四个公式与一张符号表

本节结论：学生侧是「可导的预测分布」，教师侧是「不回传梯度的目标分布」，损失是软标签交叉熵；教师与中心都不通过反向传播更新。

2.1 符号与代码变量对照

符号 论文写法 代码变量 本集取值 说明
学生网络 g_θs gs ViT-S/16 有梯度，被优化器更新
教师网络 g_θt gt ViT-S/16 无梯度，EMA 更新
两个视图 x1, x2 ~ Aug(x) x1, x2 加高斯噪声 同一张图的两个版本
输出维度 K output_dim 128 论文常用 65536
学生温度 τ_s tps 0.1 较大，分布较平
教师温度 τ_t tpt 0.07 较小，sharpening
EMA 系数 λ l 0.6 论文 0.996 → 1
中心动量 m m 0.5 论文 0.9
中心 c C 全零 (128,) 教师 logits 的滑动均值

2.2 四个公式

公式一 · 学生分布（梯度从这里走）

P_s(x) = softmax( g_θs(x) / τ_s )

公式二 · 教师分布（sg 表示 stop-gradient）

P_t(x) = softmax( ( g_θt(x) − c ) / τ_t ) , sg

减 c 是 centering，除以更小的 τ_t 是 sharpening。

公式三 · 损失（两个视图交叉配对，两视图时除以 2）

L = ½[ −P_t(x2) log P_s(x1) ] + ½[ −P_t(x1) log P_s(x2) ]

代码里 H(target, student) = -(P_t * log P_s).sum(dim=1).mean()：

  • .sum(dim=1)：沿 K=128 个输出维度求和。因为 P_t 是软分布而不是类别 id，不能直接用 F.cross_entropy。
  • .mean()：沿 batch 的 B=64 个样本求平均，得到标量。

公式四 · 两个「不靠梯度」的更新

θ_t ← λθ_t + (1−λ)θ_s
c ← m·c + (1−m)·(1/B) Σ_{i=1..B} g_θt(x_i)

2.3 形状检查

张量 形状 备注
x / x1 / x2 (64, 3, 224, 224) CIFAR-10 放大到 224
s1, s2, t1, t2 (64, 128) 双塔 logits
C (128,) 要能广播到 (B, K)
loss () 标量，才能 backward()

要点：视频在 s = F.softmax(s / tps, dim=1) 后面特意写了注释 # (B,128)，就是在提醒这个形状。读代码时先盯住形状，很多错误一眼就能看出来。

04 / 08 · 逐段代码｜从导入到双塔

本节结论：整份代码只有五个零件——ViT 封装、数据管道、双塔、超参、损失函数；真正的「DINO」全在损失函数与训练循环里。

4.1 导入与设备

F 专门用来手写 softmax / log_softmax——DINO 的损失必须自己写，不能用 nn.CrossEntropyLoss，因为目标是软分布。timm 用来一行拿到 ViT 骨架。

4.2 用 timm 包一层 ViT

判断：这里是本集最大的简化——num_classes=output_dim 相当于直接把 ViT 的分类头当成 DINO head。论文里的 head 是 3 层 MLP（隐藏层 2048）+ weight normalization + L2 normalize + 无 bias 最后一层，输出 K=65536 维。包一层的意义是后面要建两个结构相同、参数独立的实例，也方便以后替换成真正的 head。

4.3 数据增强与 DataLoader

变换 作用 必要性
Resize(224) CIFAR-10 的 32×32 → 224×224 ViT-S/16 的位置编码对应 224 输入，不改尺寸会对不上
RandomCrop(224, padding=4) 补 4 像素边再随机裁回 制造平移与局部形变不变性
RandomHorizontalFlip() 随机水平翻转 制造镜像不变性
ToTensor() HWC/uint8 → CHW/float [0,1] PyTorch 约定
Normalize((0.5,)*3, (0.5,)*3) [0,1] → [-1,1] 三通道均值方差的简化写法

注意：这是单视图增强，一个样本只过一次 transform。真正的 DINO 用 multi-crop 生成 2 张全局视图 + 6~8 张局部视图，并叠加颜色抖动、灰度化、模糊、solarization。本集把这套机制压缩成了 4.6 节那个 augment()。

4.4 双网络初始化与中心 C

  • gs / gt 对应 g_θs / g_θt。命名里的 s/t 也带到了输出上：s1,s2 是学生，t1,t2 是教师。
  • load_state_dict 让教师从学生完全相同的参数起步；省掉这步，第 0 步两边输出就不一致，EMA 也会被污染。
  • C 形状是 (128,)，才能广播到 (B,128)。

判断：optimizer = optim.SGD(gs.parameters(), ...) 只吃 gs，for teacher_param, student_param in zip(gt.parameters(), gs.parameters()) 只手动改 gt——教师永远不进优化器，这就是 momentum encoder 的全部含义。

4.5 四个超参数

变量 作用 调大 / 调小
tps 学生 softmax 温度 太大 → 学生没主见、梯度糊
tpt 教师 softmax 温度 太小 → 目标接近 one-hot、训练不稳；论文从 0.04 warmup 到 0.07
l 教师 EMA 惯性 0.6 意味着教师一步就吃掉 40% 学生，其实很激进；论文 λ≈0.996~1
m 中心 c 的惯性 0.5 更新很快；论文 0.9

判断：这四个值是「为了让 10 分钟的代码看得懂」而设的，不是复现论文的取值。想复现请按 8.3 节的对照表改。另外 SGD 的 momentum=0.9 与教师 EMA 的 l 完全无关，别混：前者加速学生收敛，后者决定教师跟随学生的速度。

4.6 augment：最「暴力」的简化

调用两次 x1, x2 = augment(x), augment(x)，因为每次调用重新采样噪声，所以 x1 ≠ x2。

本集 toy 版 真实 DINO
视图差异来源 像素级高斯噪声 几何裁剪 + 颜色扰动 + 模糊 + 多尺度
学到的不变性 仅抗噪 尺度、视角、局部—全局语义一致
local → global 对应 无 有，这是 DINO 特征出现物体轮廓/分割感的关键

要点：正因为 DINOv2 是用 multi-crop 训出来的，它的 patch 特征才自带语义分组能力。只加高斯噪声训出来的特征不会有这种空间结构。这是「看懂这份代码」和「能用 DINO 特征」之间的分水岭。

05 / 08 · 核心｜损失函数 H 的两次写法

本节结论：H(teacher, student) 的三件事是——教师 detach + 减中心 + 小温度 softmax；学生大温度 softmax + 取 log；最后沿 K 求和、沿 B 求平均。

5.1 第一版（约 04:00，只看思路）

三个问题当场就被发现：

  1. 只做了逐元素相乘，没有 .sum(dim=1).mean() → 返回 (B,128) 矩阵而不是标量，loss.backward() 会直接报错。
  2. 温度用反了：教师用了 tps，学生用了 tpt。
  3. 没有 detach()，完全没用上 C。

于是 04:40 左右整段删掉重写。

5.2 终版（05:10 起保留到结束）

行 做了什么 为什么
(1) 教师输出从计算图摘下来 教师是目标不是预测，梯度绝不能回传到 gt
(2) 学生 logits → P_s 温度 0.1，梯度从这里流向 gs
(3) 教师 logits 减中心再除小温度 → P_t 减 C = centering 防单维霸占；/0.07 = sharpening 防均匀坍缩
(4) -(t*log(s)).sum(1).mean() sum 沿 K 维、mean 沿 B 维，得标量

注意：视频用 torch.log(s) 而不是 F.log_softmax(...)，数值稳定性略差（s 接近 0 时容易下溢）。8.1 节的修正版改用 F.log_softmax(s/tps, dim=1)。

5.3 为什么不能直接用 F.cross_entropy

F.cross_entropy(logits, target) 假定 target 是类别索引（一个整数），内部做 log_softmax + nll_loss。而 DINO 的目标是整个 K 维软分布 P_t，损失是 −Σ_k P_t^(k) log P_s^(k)。较新的 PyTorch 虽然支持 soft target，但显式写出来更能看清梯度该走哪一侧。

06 / 08 · 训练循环｜前向、损失、EMA、中心

本节结论：每个 iteration 依次做三件事——更新学生（SGD）、EMA 更新教师、滑动更新中心 C；顺序不能乱。

6.1 前向与交叉配对

这里要慢下来看：H 的定义是 H(teacher_logits, student_logits)，第一个参数被 detach + centering + tpt 处理，第二个被 tps + log 处理。所以「t2 监督 s1」应该写 H(t2, s1)。视频终稿写的 H(s1, t2) 实参顺序反了，详见 7.2 节。

6.2 优化器与反传

没有 epoch 循环、没有日志、没有 checkpoint——这是讲原理用的骨架，不是训练脚本。

6.3 no_grad 里的两件事

  • zip 把两塔参数逐一对齐，l*teacher + (1-l)*student 就是 EMA。这些是参数层面的手动赋值，不是可微操作，所以显式放进 no_grad()。
  • torch.cat([t1, t2]) → (2B,128)，.mean(dim=0) → (128,)，正好和 C 同形，对应论文公式里的批次均值。

要点：08:00–09:20 讲的是这行为什么是 dim=0。沿 dim=0 得到「每个输出维度平均有多大」，才是要被扣掉的中心；写成 dim=1 会得到 (2B,)，含义变成每个样本在 K 维上的平均概率（恒等于 1/K），完全没意义。

07 / 08 · 代码里的五个问题与修正

本节结论：终稿里前三个问题会让训练实际上学不到东西，后两个是工程规范问题。下面是明确判断，不是待商榷的建议。

# 位置 问题 严重度 修法
1 loader / dataloader 变量名不一致 运行即报错 统一命名
2 H(s1, t2) 实参顺序反了 学生完全不更新 改成 H(t2, s1, C)
3 def H(..., C=C) 默认参数绑定陷阱 centering 恒为 0 显式传 C + C.copy_()
4 gt(x1), gt(x2) 教师前向没禁图 白建图、费显存 包进 no_grad()
5 zero_grad() 位置 放在 step() 之后 可用但不规范 移到 backward() 之前

7.1 变量名不一致

现场敲码的手误，统一成 dataloader = get_dataloader(batch_size) 即可。

7.2 实参顺序反了（最严重）

并排看定义与调用：

后果链条：

  1. s1（学生输出）被 detach() → 学生对 loss 的梯度路径被切断；
  2. t2（教师输出）被 softmax(.../tps) 且没 detach → 梯度反而流进 gt；
  3. optimizer 只管 gs.parameters() → 这批梯度永远不会被用上；
  4. gs 一步也没更新，下一轮 EMA 只是把两个随机初始化的网络互相搅一搅；
  5. loss 停在常数附近，两个网络都停在随机特征上。

修法：loss = (H(t2, s1, C) + H(t1, s2, C)) / 2。更不容易错的做法是把形参直接改成 H(teacher_logits, student_logits, C)，让名字自己说话。

判断：detach 的那一侧必须是教师，保留梯度、log 的那一侧必须是学生。这一条是判断任何自蒸馏代码对错的快速检验法。

7.3 默认参数绑定陷阱（最隐蔽）

Python 的默认参数在函数定义时求值一次并永久绑定对象。循环里的 C = ... 只是重新绑定名字，并没有改动 H 里那个旧张量；而且 m*C + ... 本来就新建张量、不是原地修改。于是 H 用的 C 永远是初始全零 → centering 形同虚设，只剩 sharpening 单腿站着，更容易坍缩。

7.4 教师前向没有 no_grad()

t1, t2 = gt(x1), gt(x2) 会完整构建 gt 的计算图。虽然 H 里的 detach() 让梯度回不去，但图已经建了，白白占显存。规范写法是把这两行包进 with torch.no_grad():。

7.5 zero_grad() 的位置

backward() → step() → zero_grad() 能跑（等价于下一轮前梯度是干净的），但不是常规写法，中途 continue 或异常时容易隐性梯度累积。标准顺序是 zero_grad() → backward() → step()。

8.2 怎么判断「真的训起来了」

观察量 健康 异常
loss 缓慢下降并稳定 一步掉到常数不动 → 检查 7.2 / 7.3
teacher_entropy 接近但略低于 log K = log 128 ≈ 4.85 趋近 0 → 单点坍缩；恒等于 4.85 → 均匀坍缩

三个诊断实验：

  1. 注释掉 C.copy_(...)（等价于不 centering），看 teacher_entropy 是否明显下降。
  2. 把 tpt 调到和 tps 一样大（去掉 sharpening），看分布是否变均匀。
  3. 把 EMA 的 lam 改成 0.0（教师 = 学生的即时副本），看训练是否震荡——这解释了论文为什么要 λ≈1。

8.4 要点回顾

  1. DINO = 无标签自蒸馏：教师输出当软标签，学生去拟合，教师由学生 EMA 得到。
  2. 梯度只走学生；教师 no_grad + detach，这是自蒸馏与普通双塔最直观的区别。
  3. 交叉配对：t2 → s1、t1 → s2，绝不自己监督自己。
  4. 防坍缩靠两股反向力：centering 摊平 + sharpening 捏尖，EMA 让目标慢慢变。
  5. 损失是软标签交叉熵，要 sum(dim=1) 而不是 F.cross_entropy；形状 (B,K) → (B,) → 标量。
  6. 每个 iteration 三件事：更新学生 → EMA 更新教师 → 滑动更新中心 C，顺序不能乱。
